# Evidence-based TECT (local fail-closed register)

Repository: `tltmgnt/MathOS`.

This is a portable evidence register and integrity gate aligned to the *conceptual* ResearchOS/TECT policy in [ResearchOs](https://github.com/tltmgnt/ResearchOs), canonical runtime `tect_runtime` v0.1.0. It is not a replacement for the canonical controller, nor proof that other modules are integrated with it. The broad repository claim remains **UNVERIFIED**; specifically scoped local claims may become **SUPPORTED** by passing validation evidence. No external independent reproduction or real-world authorization is asserted.

Run `python3 evidence_tect/check.py --self-test` then `python3 evidence_tect/check.py`. CI executes both, using only synthetic self-tests and repository-local records. An exit code of 0 means **record consistency only**, never truth, performance superiority, policy approval, or safe deployment.

For each claim, record a versioned statement, bounded scope, provenance anchor, assumptions, limitations, dependencies and declared state. Evidence records must bind claim ID/version, kind (validation, attack, reproduction, contradiction), PASS/FAIL/UNCERTAIN, actor, source ID, method, group, scope, assumptions, timestamps with timezone, in-repository artifact path, and matching SHA-256 digest. Attack records require one of the three canonical attack classes. Review records must bind scope, reviewer, policy version, time window, and checked artifact digest. Missing, future, expired, tampered, conflicting, or revision-mismatched records fail checks. Promotion requires passing validation; stronger states add attack coverage, separately declared reproduction, and review. **ASSURED always blocks without an external trust and governance mechanism** (not implemented here).

Known limits: SHA-256 integrity is not source authentication; different declared provenance groups do not prove independent observers; a self-declared review is not identity verification; a synthetic PASS is not empirical reproduction; no clinical, trading, civic, defense, robot, facility, or laboratory action is authorized. New evidence must be independently sourced, rights-cleared and scoped. Existing domain tests and `docs/researchos/` artifacts remain authoritative only for what they actually demonstrate.

## Bounded polynomial validation

Run `python3 evidence_tect/validate_polynomials.py --check` (Python 3 and a C++17 compiler, default g++). This compiles the actual model and exhaustively checks 24,336 ordered input pairs: coefficient-vector lengths 0–3, coefficients −2 through 2. A Python arbitrary-precision integer Horner-evaluation oracle checks five distinct points (sufficient to identify polynomials of degree at most four), result shape, and a deliberately incorrect product. The deterministic report binds the model SHA-256 and is compared on every workflow run. The evidence register binds the committed report digest; changes require reviewed evidence updates, not silent rewriting of the report. Passing supports only the specified finite claim; it is not independent scientific validation. Scope-mismatched validation and unresolved in-scope failed tests cannot promote a claim.

External advancement requires a genuinely separate operator, independently obtained evidence, scoped review, authenticated identities and explicit governance authorization. See [external validation guide](../docs/EXTERNAL_VALIDATION.md). No local CI test can substitute for these controls.

Adversarial replay: `python3 evidence_tect/adversarial.py` tests the actual registered bounded claim on a temporary copy and compiles an intentionally faulty multiplication implementation. CI also repeats the exact oracle using Clang. These are local robustness checks, not independent scientific reproduction. Higher states requiring independent reproduction remain blocked until a genuine authenticated mechanism exists.
