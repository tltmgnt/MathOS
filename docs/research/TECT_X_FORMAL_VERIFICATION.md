# TECT-X independent Lean kernel certificates for finite topological deductions

**Public-facing product identity:** **Remetheon Kernel**, part of [REMETHEON — Mathematical Memory Intelligence](../brand/REMETHEON.md). This name refers to the existing scoped TECT-X formal verification tooling; it does not claim general theorem proving.

**Implemented artifact:** [finite F₂ graph-chain proof](../../formal/TECTXFiniteTopology.lean) +
[independent theorem-type contract](../../formal/TECTXFiniteTopologyContract.lean) +
[pinned Lean replay auditor](../../mathos/research/tect_x_formal_certificates.py).

**Current trust boundary:** A successful *actual* Lean 4.14.0 replay kernel-checks the
four precise finite propositions below. It does not validate the semantic
correctness of every authored TGA proof edge, verify human mathematical prose,
discharge any RH/BSD/Selmer obligation, or replace independent mathematical
review. The [formal manifest](TECT_X_FORMAL_CERTIFICATES.v1.json) starts at
`PENDING_ACTUAL_KERNEL_REPLAY`; a source-only audit reports `NOT_RUN`
regardless of tests passing.

## What is mathematically checked?

All edge coefficients are Booleans, representing `F₂`, with the boundary of a
vertex given by XOR of incident edges. These are real, fully quantified finite
chain-complex deductions rather than truth values copied from Python.

1. **C₄ graph:** The kernel of the four-vertex incidence boundary consists
   exactly of the zero chain and the full four-edge cycle. Therefore, with
   no 2-faces, its one-dimensional cycle space is generated by one cycle.
2. **Three-edge path:** Its incidence-boundary kernel contains only the
   zero 1-chain, giving no first homology in the one-dimensional model.
3. **Filled triangle:** The boundary of either zero or unit 2-chain has
   zero vertex boundary (explicit `∂₁∂₂=0`).
4. **Filled triangle's H₁:** Every 1-cycle is either zero or the
   boundary of the unique triangular 2-face. Therefore its H₁ is trivial.

The [independent contract](../../formal/TECTXFiniteTopologyContract.lean)
spells out the XOR boundary formulas separately and passes each asserted
theorem at **its exact expected Lean proposition type**. A theorem name by
itself or a self-declared `verified` field is not accepted.

## Actual verification procedure

Use the **pinned** `leanprover/lean4:v4.14.0` toolchain in a disposable,
credential-free environment. Source code can execute Lean metaprograms;
do not run untrusted patches on a sensitive laptop or a machine containing
secrets. The CI runner uses a fresh GitHub-hosted environment without
checkout-persisted credentials; full network isolation and binary supply-chain
attestation remain additional hardening work.

```sh
# Static checks ONLY. Never reports kernel success.
python -m mathos.research.tect_x_formal_certificates

# Requires installed Lean 4.14.0; compiles the proof module and the
# separately authored type contract, checking #print axioms for every theorem.
python -m mathos.research.tect_x_formal_certificates \
  --check-lean --lean lean \
  --report artifacts/tect-x/formal/assurance.json \
  --artifact-dir artifacts/tect-x/formal

# Adversarial regression tests for fail-closed controls.
python -m unittest discover -s tests -p 'test_tect_x_formal_certificates.py' -v

# Integrate a real kernel replay with TGA without closing any conjecture.
python -m mathos.research.tect_x_intelligent_proof_verifier \
  --verify-lean-certificate --lean lean \
  --report artifacts/tect-x/formal/tga-with-lean.json
```

Only successful, warning-free Lean compilation plus the independent
theorem-type contract and **four unambiguous zero-transitive-axiom reports**
can produce the status `LEAN_KERNEL_CHECKED_FINITE_F2_DEDUCTIONS_ONLY`.
A wrong/missing Lean version, any compiler error, any `sorryAx` or custom
axiom, or an ambiguous/missing axiom report causes a nonzero exit.

The report records the verified theorem names, SHA-256 source/contract
digests, exact Lean version, explicit axiom inventory, and immutable
`closed_conjecture_obligations: []`. A generated `.olean` is emitted only
after success; do not trust a binary artifact instead of repeating kernel
replay against the tracked source.

## General bounded graph-cycle certificates (extension)

The [graph-certificate manifest](TECT_X_FINITE_GRAPH_CERTIFICATES.v1.json)
contains five finite graph 1-skeleta: a path, a square, a diamond, a
disconnected graph and K4. The
[general graph certificate generator](../../mathos/research/tect_x_general_graph_certificates.py)
computes H0 with **two independent Python algorithms** (BFS and union-find),
generates a mod-2 incidence matrix, computes its nullspace with Gaussian
elimination, and independently enumerates **every** bounded edge subset.
It rejects mismatched claimed Betti numbers and malformed or excessive input.

More importantly, for **each** accepted graph it emits two new Lean theorems:

1. `cycles_exact`: universally quantifies all edge choices and proves that
   the complete incidence kernel consists exactly of the enumerated F2
   linear combinations of the candidate cycle basis.
2. `basis_independent`: universally quantifies the basis coefficients
   and proves that only the all-zero coefficient vector maps to zero.
   Acyclic cases are proved vacuously.

This yields **ten additional formally checkable theorems** across the five
registered graphs. The generated Lean source uses only `Init`, explicit
Boolean equations, case splitting and `decide`; `#print axioms` must
confirm **zero transitive axioms for each theorem**. A source or mock test
is never treated as a kernel verification. The GitHub workflow actually
installs Lean 4.14.0 and checks all ten theorems with a zero-axiom policy.

**Exact scope:** Simple undirected graphs with up to seven vertices,
eight edges, and four independent cycles. These are one-dimensional
graphs with **no filled 2-cells**. A result about their cycle space is
not a persistent homology theorem, does not characterize zeta zeros,
and is not a proof that TGA works on arbitrary sized graphs. H0 is
cross-checked in Python; the exact finite F2 cycle space and basis
independence are kernel-checked.

```sh
# Source-audited Python preflight, NOT a kernel certificate.
python -m mathos.research.tect_x_general_graph_certificates

# Actual pinned Lean kernel replay (saves generated theorem source).
python -m mathos.research.tect_x_general_graph_certificates \
  --check-lean --lean lean \
  --report artifacts/tect-x/general-f2/report.json

# Use within the TGA command while preserving all conjecture blockers.
python -m mathos.research.tect_x_intelligent_proof_verifier \
  --verify-general-graph-cycles --lean lean \
  --report artifacts/tect-x/tga-general.json

python -m unittest discover -s tests -p 'test_tect_x_general_graph_certificates.py' -v
```

The workflow also performs a **real negative-control replay**: it appends
a deliberately false finite F2 parity theorem to the previously accepted
generated Lean source and requires the pinned checker to reject that file.
This detects an accidentally permissive invocation or status parser; it
still does not constitute independent assessment of the modeled mathematics.

**Trust boundaries remain:** The manifest chooses what graph and proof
target to study; its endpoints and correspondence to the intended
research math require human review. Lean proves the finite propositions
the generator actually submits, not the validity of the author's
broader conjecture. Recompiling saved Lean text independently improves
reproducibility, but source digests are not cryptographic author attestations.

## Relationship to intelligent Topological Gap Analysis

The [TGA proof-gap analyzer](TECT_X_INTELLIGENT_PROOF_VERIFIER.md) constructs an
undirected **dependency graph 1-skeleton**, computes its H0 component count
and H1 graph-cycle rank, and reports authored logical route gaps.

The formal lemmas independently validate the **finite chain mathematics
of representative graph patterns**. They do not prove the Python TGA
implementation correctly computes H0/H1 for every input, and do not formalize
the general Euler-cycle-rank theorem `β₁ = |E| − |V| + β₀`. That more general
refinement and any claimed correspondence from a TGA model to a conjecture
remain separate work.

A complete mathematical proof-verification pipeline would additionally need:
precisely typed mathematical goals in Lean/Coq; checked proof terms for every
inference; a proved translation from user language and TGA graph labels
into the formal propositions; explicit axioms/import trust; and external
mathematical review of the definitions and intended meaning.

**Safety rule:** Never turn a local kernel certificate for a finite
combinatorial sublemma into an unconditional RH, BSD or Selmer declaration.
