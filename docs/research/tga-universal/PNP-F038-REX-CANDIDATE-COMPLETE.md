## 1. Contract and producer theorem

Given domain size m>=2, eliminated variable v, outgoing scope h with <=3 distinct variables not including v, and a constant number r of explicit allowed-tuple factors with scopes of width <=3 contained in h union {v}. The caller provides the factor tables, not membership results. For a candidate c=(q,a), q in [m]^|h| and a in [m], its exact feasibility is

    C(q,a) = AND_i [ projection_i(q,a) in F_i ],
    H(q) = OR_a C(q,a).

If no factors are touched, generate a single true zero-scope dummy factor (empty tuple present), so every candidate has at least one request. An explicit empty allowed relation remains false, including a zero-scope empty relation. The producer validates finite host dimensions, distinct scopes, and canonical valid factor tuple digits. The adapter is scoped to the existing normalized bag width and bounded factor count, not arbitrary CSPs. The original SEP caller retains untouched factors, including untouched zero-scope factors, in its factor list.

Use d=ceil(log2 m), s=ceil(log2 r) (zero namespace bits if r=1), b=|h|+1, w=max(b*d,s+max_i |scope_i|*d), k=w+1. Encode every digit with d fixed-width bits, factor namespace i with s bits, and pad the remainder of the lookup field with zeros to width w. Lookup key = namespace || projected digits || padding, followed by role bit 0 (factor record) or 1 (request). For a fixed namespace the scope and digit count are known, so padding does not create collisions; distinct namespaces cannot collide even for identical projected tuples or zero-scope factors. Candidate alternate key = 1 || full (q,a) digits || padding; outgoing key = 1 || q digits || padding. Factor alternate keys are all-zero. All composite/alternate keys have width k. Retain namespace in the payload suffix. The three initial result bits are zero. This obeys the REX-006 three-key grammar without externally computed feasibility flags.

Enumerate candidates in outgoing-key order then eliminated digit order. A chunk contains at most cap whole candidates; append exactly one request for each of its r factors and copy every allowed factor row into each chunk. No candidate split into partial conjunctions. The code reverses the prepared record array before invoking the worker, so sorting is not supplied for free. Each candidate is generated exactly once; for any candidate the requests range over all factors, membership is exact by namespace injectivity, and its group is the projection q. These properties establish the REX-006 semantic promises by construction rather than expecting the grammar to validate coverage. The reference worker and physical worker compute the same result on their contract.

## 2. Message union and witness provenance

Read positive outgoing flags from every completed batch and union their outgoing keys. Since batches partition the full candidate space, the union is exactly H. The producer retains no entire candidate space: only a chunk of cap candidates, a copy of factor records, one worker result at a time, and bounded outgoing sets/maps.

New important acceptance boundary: the last outgoing representative holding OR=1 need not itself have a true candidate conjunction. For a unary factor allowing digit 0 and not digit 1, both candidates belong to the empty outgoing key; the last candidate is infeasible but holds OR=1. The actual physical worker reproduced this case. Using its outgoing-flag row as a witness would produce an invalid eliminated digit. Instead recover a from the retained candidate key on any row with candidate AND=1, and take minimum such a within the group and across batches. The adapter checks equality between positive outgoing groups and groups with a positive candidate flag. This produces an explicit witness for every positive message entry. The minimum rule is deterministic and the direct oracle checks it. A witness obtained from the candidate flag belongs to the same outgoing group by producer construction and satisfies every touched factor. Retire OR representative implies feasible candidate.

A second actual physical control uses two namespaces with one factor permitting only 0 and the other only 1. The intersection is empty even though their unnamespaced union contains both digits. Namespace is essential. Separate logical controls cover the true dummy and a two-variable bag with a batch boundary inside an outgoing-key group. The producer's whole-candidate chunking is the remedy for the REX-006 split-request counterexample; outgoing-key groups themselves MAY safely cross chunk boundaries. Empty outgoing scope is represented by one padded role-one group. Absent/false groups are not emitted as positive messages.

## 4. Charged resource ledger (conditional)

For constant-many factors (there are only constantly many scopes on nine groups and a constant number of elimination messages), k=O(log(m+2)). At most O(m^3) allowed tuples per factor. With production cap m^3, factor copies and complete requests require N=O(m^3 log(m+2)) bits per batch, including namespaces, alternate keys, payload, delimiters and duplicate copies. No materialized m^4 bag. For a bag with b<=4 variables, the number of chunks is ceil(m^b/m^3)<=m+1. In the inherited sliced plan, with s_cut conditioned coordinates and q_slice outer slice coordinates for a dynamic component, q_slice+s_cut+max(3,b)<=5; static components omit q_slice. Thus across slices/conditionings the total number of batches of a fixed bag is at most O(m^(q_slice+s_cut+max(0,b-3)))<=O(m^2), and the constant number of bags preserves the bound. Reconstruction repeats a bounded subset of the same calculations. The production cap is essential to this accounting; stress cap m^2-1 is not asserted to satisfy it.

A proposed fixed sequential producer can enumerate with a constant number of O(log m)-bit counters and write the namespace/projection requests without querying a factor table per candidate; the allowed tuples are copied by sequential scans. Per batch generation and decoding use O(m^3 polylog m) sequential work and span. The positive outgoing relation and local witnesses can be merged by outgoing key in sequential passes, because worker output is outgoing-key sorted; group-local minimum is a sequential reduction and the global merge uses minimum of witnesses for shared keys. This requires no expansion to the full m^4 candidate space. If the producer, persistent factor/cursor storage, merge, scratch cleanup, and fixed-workspace relocation can all be realized within O(N^2 polylog m) physical work per chunk and O(m^3 polylog m) span, the implemented REX-006 worker contributes Theta(kN^2) per chunk and the resulting bag lifecycle would fit O(m^8 polylog m) total. This is a sufficient conditional ledger, not an executed physical producer/merge. Standalone REX-006 consumes its input and moves output left of the initial region; repeated external calls do not automatically give a bounded same-tape workspace or preserve factor history. The raw-to-record generator and entire lifecycle still need fixed-rule implementation and physical cost proof, as do original raw preparation, complete key joins and original witness output. The host Set/Map and built-in array operations are not charged physical transitions. No exact U stage admission, unrestricted completeness or P versus NP consequence.
