## 4. Explicit physical filter operation

The extra operation is not implemented by an uncharged random-access join or a full six-coordinate expansion. In a side-t projected frame there are O(t^3) selected forbidden records on supports of width<=3 inside P (constant-many supports), plus padding units. They are translated to local digits, with O(log(t+2)) bits per field. The candidate map stream has at most t^4 records of actual four-coordinate keys and root/target references.

For a fixed map record z, test all local x candidates 0..t-1 and then all local y candidates 0..t-1. Padding units make nonreal candidates fail. To test one candidate v, scan the projected original record list, ignoring records whose support is not in A union {v's group}; compare the remaining record's digits with the fixed local key and candidate. Failure iff a forbidden record matches. This also tests all A constraints. One can explicitly test A first and short-circuit either existence scan; this does not change the worst bound. At most O(t) candidate scans per map key. Each scan costs O(t^3 polylog(t+2)) PHYSICAL moves within a contiguous copy of the original projected records, NOT the square of that span: carry the O(log(t+2))-bit key/candidate/counter on a small mobile component across that record copy, comparing fields in O(polylog(t+2)) local moves per record. The inherited constant-width product-track encoding and carry-shift operation move this small component by one position with O(polylog(t+2)) overhead, preserving the record component. Rewind it after each scan; all distances within O(t^3 polylog(t+2)). This nested use of a small mobile key inside a larger scratch interval is essential to the stated cost; a full-frame sweep per candidate would not give the bound.

To access the t^4 map records without repeatedly crossing the whole frame, copy the projected original list into a contiguous mobile scratch component of extent O(t^3 polylog(t+2)), and move it along the stationary map stream. Park it at the current record, read the key and mark its eligibility bit, then continue. One-position shift of the larger scratch costs O(t^3 polylog(t+2)) using inherited carry shifts, so traversing O(t^4 polylog(t+2)) map-stream positions costs O(t^7 polylog(t+2)). Moving it from/to its original location across an entire cap-bounded frame costs at most O(C*t^7 polylog(t+2)). While parked, use the small-key scan just described, not a move of the entire large scratch per comparison. O(t^4) records times O(t) scans times O(t^3 local-log) physical cost yields O(t^8 local-log). Combined filter cost O((t^8+C*t^7) local-log), bounded by O(C^2*t^8 local-log) for C>=1.

All scratch components use a fixed number of product tracks, encoded in constant-width blocks over the actual symbols 0,1,2, with a single physical head. There is no input-dependent alphabet, extra physical head, global index or random access. The scratch holds only the translated original projected list and a fixed number of O(log(t+2))-bit fields. At child size u=t/2 work may be performed in the parent-sized interval prior to compacting the child; ratios of cap-bounded upper extents are fixed. This costs at most the parent local charge even if the actual child payload is much smaller. Local counters and capacities use local-width fields, clipped as in the prior workers. No log m fields accompany small descendants.

This is an explicit resource-accounted extension of the inherited mobile scratch primitive; actual transition-level composition and encoded move counts have not been implemented. If the primitive or its fixed-track composition fails in a physical implementation, the bound must be rechecked.
