## 2. Exact recognition theorem

Use nine latent groups of m>=2 real digits, n=19m-7 Boolean variables. The original input is a unary header 1^n 0 followed by one binary selector bit per clause in pool(n): widths 1,2,3, increasing absolute support lexicographic order within width, sign tuples in (-1,+1) lexicographic order. Its length is

    L=n+1+2n^2+8 binom(n,3)=Theta(m^3).

The recognized language is exactly the normalized construction in f038_unrestricted_distributed_hyperclique.py with r=9: fixed onehot/OR chain clauses, two negative guard units, four lifted pin clauses per pin with a common sign, and any subset of all-negative cross clauses on distinct onehot groups of width 1..3. Reject other selected clauses, missing required clauses, incomplete or mixed-sign pin groups, invalid header/dimensions, nonbinary symbols, and truncated or extra bits. The header determines m; no advice or external latent model is supplied. This is a deliberately strict recognizer, not a parser for every equivalent CNF presentation.

Algorithm: regenerate the fixed non-pin clause list (normalize by absolute variable index); traverse the original selector in exact pool order; for each selected bit either consume a required non-pin clause, count a pin sign/guard combination, or extract its all-negative distinct-group digit tuple. Pool enumeration has no duplicate clauses. Each pin sign has exactly four possible guard-sign combinations, so a count of four of one sign and zero of the other is equivalent to the required four distinct lifts with consistent sign. At end all required clauses must have been consumed. The three categories are disjoint: within-group negative pairs in the fixed onehot constraints do not count as cross clauses; auxiliary and pin/guard variables lie outside the onehot index range; required clauses contain no pin variables. Thus acceptance is iff the input has the required normalized format. This claim is semantic; the JS uses host sets, arrays and numbers.

Fixed onehot clauses enforce exactly one true X per group: negative within-group pairs give at most one, and OR-chain equivalences plus the final positive OR unit give at least one. For digit a_g (zero-based) the unique chain extension is Y_g[i]=[a_g<=i+1]. Both guards are false, so the appropriate pin literal is forced by the lift with both positive guard literals; the other three lifts are then satisfied. A negative cross clause is false precisely at its specified latent projection. Consequently original satisfying assignments correspond bijectively to latent tuples avoiding all extracted forbidden records, with the uniquely fixed auxiliary and pin extension. This proves that exact decision and witness reconstruction on the extracted relations preserve original SAT/UNSAT, not merely a proxy constraint system.

## 3. Integrated executable host solver

The standalone Node-compatible f038_tga_normalized_integration.js accepts raw bits on stdin with --solve (no whitespace trimming). It uses the decoded selected scopes to try the inherited SEP-002 structural planner over four-key partitions, retains static component messages, builds dynamic messages slice-by-slice, and uses sorted merge membership for both streamed elimination bags and the key join. Unlike the SEP-002 audit, no dense reference candidate bag is used in the integrated solve path, and no global set of all feasible keys is retained by the solver. The finite audit independently builds reference key sets outside solveRaw. In the streamed bag loop candidate IDs are sorted back to their initial order after each factor membership join; existential OR crosses batch boundaries. Key and bag batches in the final --solve path contain at most m^3 tuples. A separate stress mode uses the smaller inherited bag cap m^2-1 to force boundary splitting. Both modes were executed on all 18 normalized instances and their complete output records matched. The smaller cap could add a factor m to a full-table scan ledger, so only the production cap is used in the proposed bit complexity proof. No claim that the JS host runtime satisfies the O(m^8) physical bound. Host factor lookup in conditioning/reconstruction and built-in sorting remain, not physical tape operations.

The four terminal labels are distinct:
- SAT: admitted normalized instance, exact nonzero key count, actual n-bit witness emitted and checked against all original selected clauses.
- UNSAT: admitted normalized instance, complete exact sliced search returns zero keys.
- INELIGIBLE: normalized but the specific structural planner rejects every candidate partition. No satisfiability inference.
- OUTSIDE_NORMALIZED: parser rejects. No satisfiability inference.

The selected witness is constructed by rerunning its successful slice and reversing each component elimination, combining private digits with the actual full key, then producing onehot bits, OR-chain auxiliary bits, pins and guards in original variable order (least significant variable first). Full original-clause verification is performed on the actual raw selector and emitted bits. This is host semantic integration, NOT a call to tape_run and NOT a compiled descriptor or contiguous physical halt output. In the general U enumeration the failed worker must not emit an invalid acceptance: for an unsupported or UNSAT case a future machine can halt with a blank under its head, while other algorithms remain responsible for broader coverage. The host labels are diagnostics; U's witness-only return protocol cannot distinguish these failure reasons.

## 4. Complexity auditor: explicit parser and output ledger

A fixed multitape bit implementation can generate the width<=3 pool with a constant number of binary counters of O(log n) bits, scan the raw selector in order, write selected records of O(log n) bits, regenerate the required fixed list and compare by sequential sort/merge, count the pin signs, and group/deduplicate cross records. Time and space O(m^3 polylog(m+2)); length and header checks use arbitrary-length binary counters, not JS numbers. Convert each selected cross support's forbidden records to allowed tuples by enumerating its <=m^3 possible entries and merging sorted streams. Constant-many supports. The input-side tasks therefore fit the existing preparation bound. In the proposed production solver, all bag/key chunks use capacity m^3, with full-factor scans charged per chunk as in SEP-002; static/dynamic message histories occupy O(m^3 polylog m) total bits; total bit work O(m^5 polylog m) on the admitted class. Constructing n contiguous witness bits requires actual digit and pin data, O(m polylog m) sequential operations; verifying all original selected clauses can use sorted literal requests and assignment merge, O(m^3 polylog m) sequential operations, not random access. This ledger is for the intended fixed multitape algorithm, not for the stress mode with smaller bag cap or the host code's JS numeric/domain limits. It makes the required parser and output steps explicit.

Under the inherited fixed-track physical simulation, with actual raw layout conversion and halt-output serialization still to implement, full time O(m^8 polylog m), span O(m^3 polylog m), and L=Theta(m^3) give conditional o(L^3). At stage 3 ceil(log2 L), a fixed realized program of length ell receives >=L^3/2^ell steps once eligible. No descriptor or same-program clock proof, no actual stage admission, no full raw-to-block conversion machine or final contiguous halt machine. Earlier FAR prepared mask/equality primitives do not fill this gap. The host solver is not claimed to be total on arbitrary binary strings of unbounded length in a theoretical model, because the JS runtime has finite arrays/Number limits; the mathematical decoder uses unbounded counters. No general SAT or P versus NP conclusion.

## 5. TECT-X: status and data-model controls

Mixed static/dynamic and no-cross controls exercise both static and dynamic recovery. The previous inherited structural obstructions stand.

The current integration does not demonstrate that the raw one-head tape can perform the same input preparation, batch joins and witness extraction within the analytical exponent.
