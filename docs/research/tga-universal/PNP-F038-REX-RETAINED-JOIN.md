## 1. Contract

Input is an arbitrary-order finite list of records (x b,p), where x is a binary actual key of common width k-1>=0, b is a one-bit role (0 factor, 1 query), and the composite key has common width k>=1. Payload p is arbitrary binary for factors (including empty); queries require at least one bit, reserved for the membership result. Remaining query payload is preserved verbatim, e.g. candidate IDs and full tuples. The initial flag can be either bit; it is overwritten, not ANDed with the new result. Encode a key/payload bit v as 0v, divider as 10, record terminator as 11, same grammar as REX-004. No supplied sortedness or membership flags. Empty list allowed. Raw input contiguous from head zero, blank elsewhere.

Output is the stable composite-key sorted list, retaining every factor record and all factor payload bits; for every query replace only its first payload bit by [x occurs as a factor key]. All other query bits unchanged. Result order is composite-key order, NOT original query-ID order. Duplicate factors and queries allowed. Malformed token grammar, unequal composite key widths, or missing reserved query flag halt on blank; no preservation guarantee on rejection. The worker does not discover actual keys or IDs from normalized SAT input.

## 2. Construction and correctness

Reuse the REX-004 fixed stable radix sorter and common-width validation. Instead of its normal ready transition, the logical done state moves left into joinLeft, on the SAME aligned tape with the sorted source region intact, R at its end, scratch erased. Reinstall L; scan and mark the final composite key digit of each record as role M0/M1. The output serializer is invoked only after both phases. No external reset, data copy, record permutation or membership decision at the phase boundary.

Process sorted records left-to-right using the latest factor start marker F. On a factor record, mark its start H, clear the old F if present, replace H with F and move to the next record. Keep all its data. On a query mark start Q. If no previous factor, result zero. Otherwise compare actual key to the latest factor: mark their first key-digit cells with V/U cursors, use bounded sentinel scans to read one digit at a time, advance both cursors on equality, restore them to the original digits. Treat the role markers as end-of-key (V2/U2); do not compare role values. On mismatch return zero; simultaneous end returns one. Reset cursor marks, locate the query divider, verify its first payload token is a bit and overwrite that bit. Resume processing after its terminator while retaining F. At exhaustion restore F and all role marks, remove L and enter ready with all records intact and R at the end. Projection emits the entire raw record stream; there is no interior blank or discarded factor region. The same physical descriptor erases scratch and halts at the first contiguous output bit (blank if empty).

Proof: sorting by x followed by b ensures every factor with actual key x occurs before every query with that same key. At the start of processing a query, F is the most recent factor in the sorted prefix, or absent. If some factor with the query key exists, all such factors precede the query, and no larger actual key has been processed. Thus F exists and has precisely the query key. Conversely equality with F certifies an existing factor. This equivalence holds even for empty actual keys, duplicate records and any initial record permutation. The fixed common-width comparison determines equality by checking digits until a mismatch or the simultaneous role-end markers. The update changes only the reserved flag; all other data preserved. Stable radix ordering is inherited from REX-004. Each outer iteration advances a record; each comparison advances a digit or stops; all scans are sentinel bounded on valid states. Missing query flag is rejected at the attempted overwrite. Parser and width checks are inherited. This proves the stated contract for every finite input in its domain.

## 3. Charged physical ledger

N = raw encoded bits, k = common composite width. Fixed logical alphabet 29 symbols, five-cell binary code for nonblank symbols, all-blank 22222. Moving logical transition costs 13 physical transitions, stay 9. On nonempty successful inputs preparation P(N)=6N^2+15N+3, serialization O(N)=6N^2+21N+15, same as REX-004 since all N bits emitted. Empty input total 11 transitions. The physical sort uses k passes, each with exact copy/restore work 5N^2+10N+2 logical transitions and other O(N) work. The join phase uses O(N) tagging/cleanup and O(N) scans per processed record plus O(N) per compared key digit (including the end marker). The number of compared symbols is at most q*k for q query records, which is O(N) since query records encode k digits. The flag write and resume scans are bounded by O(N) per query, including the extra F recovery sweep. Factor replacement scans likewise O(N) per factor. Hence join work O(N^2), physical join work O(N^2), with no additional destination region. Sorting dominates and the actual full machine has Theta(k N^2) time on valid nonempty inputs; physical span exactly 11N+12, output head -6N-2 (empty span 5 and head zero). Bound includes raw conversion, same-machine boundary, scratch erasure, and contiguous output. No claim that every possible sorting algorithm has this cost.

For fixed-width tuple keys k=O(log(m+2)) and prepared batches N=O(m^3 polylog(m+2)), this gives O(m^6 polylog m) per batch; at O(m^2) such batches the primitive cost is O(m^8 polylog m). This is conditional compatibility with the SEP ledger, not a proved complete solver call bound. The new worker supports one factor relation at a time: later multifactor computation must preserve earlier feasibility flags (AND not overwrite), extract/rekey tuple projections, re-sort by IDs or outgoing keys, combine and reduce, regenerate/reuse factors, maintain bounded chunks and reconstruct actual witnesses. Actual normalized raw parsing and tuple production not compiled. No claim of exact eventual U admission or uniform SAT complexity.

## 5. TECT-X and status routes

Role suffix ordering is essential to latest-factor correctness: with arbitrary ordering, a later factor can match an earlier query and be missed. The same-machine sort enforces the required order. A role prefix instead of suffix would segregate all factors before queries, making latest-factor equality insufficient. No claim of general record join for arbitrary key encoding. Stable ordering within composite-key ties does NOT recover original ID order across different keys. Query flags overwrite, so sequential independent factor calls on the same flag do not implement conjunction without another mechanism. These are explicit boundaries, not impossibility results against alternative algorithms.
