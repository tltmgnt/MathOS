## 2. Tagged relation representation

For the chosen ordered pair (u,v), let S be the other seven groups, ordered by group index. Let G_u=S union {u} and G_v=S union {v}, both of size eight. Apply the parent's exact rectangle construction: for each color A_k of u, remove all clauses containing both u,v; restrict u to A_k; and replace each pair-context slice by its equivalent separate unary/binary exclusions on u and v with the third-group context if any. The branch solution sets are disjoint, with union exactly the original solution set, and each surviving tuple retains its original full assignment including actual pins.

Represent all branches together without making K copies of the large unchanged ternary lists. The common records are the original selected cross clauses NOT containing both u,v. Each is owned by the unique containing bag, or by G_u if both contain its support. The extra records are tagged by color k, and consist ONLY of the replacement and color-class unary/binary exclusions. Each is owned by its containing bag (the exclusions all involve u or v). Interpret a record with a common tag as active in every color; a record with a color tag is active only in that color. Duplicates can be OR-deduplicated or treated as separate forbidden records. Fixed layout clauses need not be copied into these internal local relations: as before, the original fixed extension is unique and reconstructed on success.

Globally there are O(m^3) common records and at most O(K m^2) extra records (constant many support types per color), hence O(m^3) in total because K<=m. On a bag tile of uniform width b, restriction and subtraction of offsets retains O(b^3+K b^2) records, plus O(b) common unary padding records. This is O(b^3) whenever K<=b. The count includes empty-row replacement clauses, even when a color has no available value in a private block. Record tags, supports, coordinates and counters require O(log m) bits. No implicit tensor of K copies of the original ternary data is materialized.

The parent's explicit slice comparisons and coloring require O(m^4 polylog m) multitape bit steps, O(m^3 polylog m) visited span. After choosing the pair, generate the common records once and the extra records for all colors using the parent's per-color replacement procedure, writing only the tagged unary/binary records rather than full selectors. Even a separate scan per color costs at most O(K m^4 polylog m) bit steps and O(m^3 polylog m) span (including all stored tags). Sort/merge by tag, support and digits if needed. The inherited fixed-track single-tape sweep simulation and raw input expansion charge O(K m^7 polylog m) original steps. Actual pins are recovered during parsing. ## 3. One extraction for all colors on a tile

Fix b>=K and b<=m. Split domains into consecutive b-wide intervals with possibly short last intervals. Enumerate common separator block-index vectors. For each such vector and each side independently, enumerate the block index of its single private group. This yields O((m/b)^8) bag tiles in total, up to a fixed constant for the two sides. Both sides hold the same separator-block index while computing their accumulators.

Store the original common and tagged owned record lists on stationary components. For a tile, scan the relevant lists once. Restrict all records by coordinate offsets, translate retained digits and add common forbidden unary padding for all out-of-range digits. The entire mobile extraction component has O(b^3 polylog m) blocks by K<=b, even when all colors' replacement clauses are dense. As in the parent aligned-separator note, move this component with the stationary scan head by one-block carry shifts preserving other tracks, then return to the fixed work origin. Charge O(m^3 b^3 polylog m) physical transitions per tile. The accumulator components do not move during extraction. Crucially this cost is paid once per side/tile, NOT once per color. No storage of a separate width-b copy of common data for every color is needed.

## 4. Color-major aligned message interface

Use the parent's encoded-track local eight-group message subroutine at scale b, with inner width d=Theta(b^(1/4)), time O(b^10 polylog m) and span O(b^7 polylog m). It outputs dense padded separator-key slots in the prescribed block-major order, with validity flag and representative fields of a common O(log m)-bit width. The caller and both bags use identical layout parameters. This is an internal interface on the original three-symbol tape, not a raw U output format. In particular the local subroutine preserves caller components and returns to its marked origin. See the parent's construction, which explicitly charges the relocatable input anchor and avoids quadratic raw conversion.

The outer accumulators have K consecutive color sections; each section has exactly the local dense padded message extent O(b^7 polylog m), including invalid keys. They are stationary, aligned on two distinct components at the fixed work origin. For a tile, place the extracted tagged records and loop metadata in a relocatable component at the start of the first section. At color k's anchor scan this component and produce a separate local list containing only the common records and records tagged k, stripping tags. A quadratic setup O(b^6 polylog m) suffices. Run the fixed local subroutine on disjoint scratch and output components at this anchor, preserving the extracted tagged data and both outer accumulators. Merge its output by an aligned sequential scan into that side's color-k section, translating representative fields by outer tile offsets, OR-ing validity and retaining any valid representative per key. Clear the local scratch by marked extents. One local call and merge costs O(b^10 polylog m), independent of K.

Move the ENTIRE extracted tagged component and color loop metadata to the next section start by carry shifts along distinct product components, leaving accumulated message slots unchanged. A component of O(b^3 polylog m) blocks travels O(K b^7 polylog m) logical cells over all colors, charging O(K b^10 polylog m) moves. Include return to the initial anchor or clearing and rewind after the last color within the same bound. This explicitly pays for bringing the tile data to each color section; no free random access to a remote accumulator or color-specific table is assumed. The cost per tile after extraction is O(K b^10 polylog m), and the total visited span near the origin is O((b^3+K b^7) polylog m), including all local scratch. Only a fixed number of tracks is needed: colors are consecutive regions on the SAME components, not K extra physical tracks or K separate finite-control machines. The parent local message routine's fixed levels are incorporated into fixed control.

For a fixed separator block, union representatives over all private blocks, but only in matching (color, key) slots. The accumulated side's slots for color k are exactly the projection of that side's local satisfying tuples in branch k, restricted to this separator block. Padding forbids out-of-range digits. This follows from exact tile restriction and union: every feasible tuple belongs to one tile and every retained representative is valid. When both sides are done, intersect their validity flags in one scan over the color-major sections. Matching color is essential: a common separator key in different colors need not yield a valid pair. A common slot gives two representatives agreeing on S and satisfying the same transformed branch. Combining their private coordinates gives an original satisfying tuple. Conversely every original model belongs to exactly one branch and one separator block, so it appears in a common slot. On success reconstruct the original full one-hot/OR/pin/guard witness and emit its contiguous n raw bits with the final head on the first bit. On no intersection clear both accumulators and advance to the next separator block; on exhaustion halt on a blank. This is exact for SAT and UNSAT on the promise, including unique SAT. No global m^7-key or K m^7-key message is stored.

## 5. Charged time, space and balance

    O((K m^7 + (m/b)^8 * (m^3 b^3 + K b^10)) polylog m)

## 6. Strict improvement of the color-count promise

For m sufficiently large set q=floor(m^(1/6))>=9 and label each digit by its residue modulo q. On every unordered pair of groups forbid exactly the pairs whose residues match, and select no ternary cross clauses. The primal graph is complete and SAT (choose nine distinct residues). For every ordered pair, the empty-context allowed matrix has q distinct nonempty rows, one for each residue; all other context slices are full. The conflict graph is complete q-partite with nonempty parts. The prescribed greedy rule uses exactly q colors (every new part uses a new color, and subsequent vertices of a part can reuse its color). Hence K=q, independent of the choice of pair. This grows faster than m^(1/7) and slower than m^(1/5). The batched theorem applies while the earlier context-coloring cutoff does not. For K=Theta(m^(1/6)) the derived exponent in m is 62/7+5/42=377/42=8.97619..., with normalized exponent 377/126<3. This is a strict comparison of the TWO color-count promises only; this particular example also has easy structure and may be solved by earlier independent pruning theorems. It is not a hardness example or a claim of separation from every other sufficient condition.
