## 1. Result

For the full nine-group distributed family with n=19m-7, L=Theta(m^3), arbitrary negative cross-group clauses of widths 1..3 and the inherited fixed one-hot/OR/pin/guard clauses, compute a global input-dependent fanout parameter W by choosing an ordering of the nine groups and, for each new group, a parent subset of at most two earlier groups. For each such step use the maximum extension count of the corresponding local allowed table. W is the minimum product of the nine maximum extension counts, with W=0 if a local table is empty.

There is a fixed deterministic original three-symbol single-tape program, uniform in all masks and pins, with running time

    O((m^6 + m^3 W) polylog(m+2))
    = O(L (L+W) polylog(L+2)).

In particular, for every fixed 0<epsilon<=3, all SAT inputs with W<=m^(6-epsilon) are eventually covered by the original exact cubic stage, including unique SAT. This is a new structural cutoff independent of the contextual-width promise. A sufficient condition is that at most five freely chosen digits generate all remaining digits by local partial functional dependencies with at most two parents. No known algebraic labels or right-hand sides are needed. Bounded nonfunctional branching is included as well.

The algorithm does not establish a strictly subcubic upper bound on the unrestricted nine-group family (W may be m^9). The cutoff is a sufficient condition, not a lower bound on any input outside it.

## 2. Actual tables and the plan parameter

As in the contextual-fixedpoint note, for every nonempty support H of at most three groups define A_H(z)=1 iff no selected cross clause with support contained in H is violated by z. All tuples satisfying the full instance are allowed by every such local table. Conversely, a tuple allowed by every table satisfies all cross clauses, because the table for each selected clause's own support checks that clause. Each surviving tuple extends uniquely to the original witness for the fixed pins.

If any table has no allowed entry, halt on a blank: no satisfying tuple exists. Otherwise, for a group g and P disjoint from g with |P|<=2, let b(g,P) be the largest number of digits a for which A_(P union {g})(z,a)=1, maximized over z in [0,m)^P. For P empty this is just the number of locally allowed digits in g. All b are integers in [1,m] when all tables are nonempty. The bound includes keys that might not extend to any global solution.

A plan is a permutation g_1,...,g_9 together with P_i subset {g_1,...,g_(i-1)}, |P_i|<=2. Its cost is product b(g_i,P_i). Find the minimum W by subset dynamic programming: D(empty)=1 and

    D(S union {g}) = min(D(S union {g}), D(S)*b(g,P))

over g not in S and P subset S, |P|<=2. Visit S by increasing cardinality (or numerical bit mask), and use a fixed enumeration/tie break. Store predecessor choices to recover a minimizing plan. There are only 512 subsets and a constant number of transitions, since the number of groups is fixed. All products are <=m^9, requiring O(log m) bits. The DP is not a search over digit assignments; correctness follows from optimal substructure because the remaining options depend only on S.

Generate candidate tuples by following the plan: for each partial tuple, append every allowed value of g_i in the selected local table at its parent key. After i steps the number of partials is at most W_i=product_{j<=i} b(g_j,P_j), and W_i<=W. Every globally satisfying tuple is generated because each of its projections passes the selected local table. No partial tuple is duplicated, by induction on the distinct preceding partials and distinct possible appended digits. Some candidates can violate other local tables; a final exact check of all supports is essential.

## 3. Precomputation and locality

Read the actual normalized input sequentially, compute m from its unary header, extract cross clause records and pin bits by the original canonical pool order. Use the previous contextual-fixedpoint construction: for each support H emit an initial record for every digit tuple and forbidden records for each completion of a selected clause of support contained in H. Across the fixed set of supports there are O(m^3) records (each width-w support contributes O(m^w) clauses with m^(|H|-w) completions). Sort by support/tuple, OR forbidden flags and complement. This constructs the local allowed tables with O(m^3 polylog m) sequential multitape bit steps and space. No RAM membership oracle is assumed.

For each possible distinguished group g within H, sort a copy of allowed records by parent key, then appended digit. Scan key runs to compute their maximum length b(g,P). Empty keys need not be stored. The number of copies is fixed, and their total length is O(m^3 polylog m) bits. The sorting, counters, fanout maxima and fixed-size DP cost O(m^3 polylog m) multitape bit work. Prepare the chosen table stream for each level. These tables encode nonlinear partial relations just as well as known linear equations.

## 4. Bounded-memory batched joins

Let C=m^3 be a record capacity (each record has O(log m) bits for a fixed-length partial tuple, ID or key). At level i, buffer incoming partials until q_i=floor(C/b(g_i,P_i)) are present. A full or final partial chunk of this size expands to at most C child records. At the end use a buffer of C full tuples for exact verification.

For a chunk at level i, sort its partial tuples by the parent key using sequential external merge sorting. Merge with the sorted allowed-table stream for that level, scanning the table at most once plus rewinds. For a matching key, copy its allowed-digit run to a small scratch tape. For each partial with the same key, scan that digit list, emit a new child record per digit, and rewind the digit list. The partial record can be held in O(log m) bits on a scratch tape and copied with polylogarithmic overhead. Unmatched partials produce no child. Both table entries and partials are read sequentially. The cost is O(C polylog m) per chunk, including the scan, sort, all <=C emitted records and rewinds. Each allowed-digit run has distinct digits.

Append children to the NEXT level's buffer. If that buffer fills, suspend the current merge/copy, process the full next chunk, and resume. Use separate fixed tapes for each level's table head, input chunk, digit-list scratch, output position and counters, so the suspended heads do not have to be recovered by a global scan at each child. There are only nine expansion levels; a finite-control call stack or fixed dispatch state suffices. Each level holds at most a constant number of C-record buffers and no unbounded accumulated output. Crucially a partly filled child buffer persists across parent chunk boundaries: do NOT flush it after every parent chunk. After the initial one empty partial has been fed through, flush the remaining partial buffers in increasing level order, with at most one final short chunk per level. This guarantees that the number of processed chunks at level i is at most W_(i-1)/q_i+1. Because b<=m<=C, q_i>=C/(2b), and this is <=2W_i/C+1. The total bit work over all nine levels is O((C+W) polylog m). The visited interval on each of a fixed number of tapes is O(C polylog m), regardless of W. This is why the construction does not need to store all candidate tuples at once or materialize an m^6 supergroup tensor.

For a final chunk assign local IDs to its <=C full tuples. For each of the fixed support tables, generate queries (projection,ID), sort by projection, and merge with the table's allowed entries. Mark missing projections as rejected IDs. Sorting the flags by ID and OR-merging with the chunk's records identifies all surviving tuples. This costs O(C polylog m) per final chunk; a query key can repeat but need only be matched against a single table entry. Thus final verification has the same aggregate bound, and every surviving tuple is exactly a global satisfying tuple. For a witness finder halt on the first survivor, or halt on blank if all chunks finish with none. The full-count reference tests below continue through all chunks; the time bound covers that larger workload except for repeated writing of full raw witnesses, which is not required.

## 5. Charged original-machine execution

The fixed sequential multitape algorithm above has time O((m^3+W) polylog m) and used interval O(m^3 polylog m) per tape, including actual input, tables, partial buffers, scratch and pin bits. The number of simulated tapes is fixed, independent of m and the plan. Apply the same direct charged one-tape simulation used in the distributed and contextual-fixedpoint notes: constant-width binary codes for finite product-track symbols and head markers, with all-2 blank blocks; raw input block expansion by shifts O(L^2); a fixed number of sweeps of the used interval per simulated bit transition. The overhead per step is O(m^3 polylog m), not O(W), because the buffers and visited extents are reused. No random access or extra physical alphabet is used. On success reconstruct the original n-bit one-hot/OR/pin/guard witness and copy it into a fresh contiguous raw region, ending at its first bit (O(n m^3 polylog m) physical moves by shuttling, dominated by preprocessing). On failure halt on blank. Therefore the time in original transitions is O((m^6+m^3 W) polylog m). The finite control and description length ell are fixed independent of the input. This is a mathematical machine-existence construction, not a generated transition table.

For W<=m^(6-epsilon) with fixed 0<epsilon<=3, the bound becomes O(m^(9-epsilon) polylog m)=O(L^(3-epsilon/3) polylog L). At j=ceil(log2 L), the exact cubic budget is 2^(3j-ell)>=L^3/2^ell once eligible; it eventually dominates the bound, uniformly on this promise. Any unbounded actual nine-group SAT misses (including unique ones) must therefore have W>m^(6-epsilon) eventually for every fixed epsilon in (0,3]. This does not assert that the condition implies failure. The earlier static/contextual pruning cutoffs still apply via their separate fixed programs.

## 6. Functional closure and nonlinear controls

A direction g <- P with b(g,P)=1 is a partial functional dependency: at each parent key there is at most one possible appended digit. If a set of at most f seed groups can be closed to all nine using such directions, a plan has W<=m^f. Hence f<=5 gives original time O(m^8 polylog m)=O(L^(8/3) polylog L) or better. This conclusion uses no uniqueness assumption and allows arbitrary partial functions. More generally if f freely enumerated groups and the remaining directions have maximum fanout product B, then W<=m^f B; a power saving below m^6 suffices. There is no requirement that the functions be affine, associative or even total. All plan information is detected from actual tables.

For the previous cyclic XOR residual on supports {i,i+1,i+3} modulo 9, each direction within a constrained support has fanout one. Seed groups 0,1,2 generate groups 3,4,5,6,7,8 in order, so W<=m^3. In fact W=m^3 for this family: all unconstrained directions have fanout m, and any two seed groups can close at most one triple, because any two cyclic supports share at most one group. Three seeds are necessary and sufficient. This gives a generic dependency-based original time O(L^2 polylog L), independent of the prior special XOR recognizer.

A stronger control hides each digit's bit-vector label via any group-specific permutation pi_g of [0,m), m=2^b. Replace each XOR equation by XOR of the three pi_g(x_g) equalling its RHS. The tables still have all local supports, all contextual signatures are incomparable, and the global solution is unique (the prior invertible linear map in the hidden coordinates). The same W=m^3 and generic solver work without identifying any pi_g, including arbitrary nonlinear permutations. More generally the sufficient condition covers arbitrary overlapping nonalgebraic tables with small fanout product whether or not the global solution set is unique.

## 7. Finite checks

Independent JavaScript enumerated the actual canonical cross-clause positions, formed closed local tables, computed fanouts and a minimum plan, and generated partial/full tuples in bounded buffers with persistent short child chunks. It compared the complete filtered model set to direct original cross-clause enumeration for 25 fixtures at m=2,3,4, including dense/empty controls, cyclic XOR, relabelled XOR, relaxed XOR and a single functional ternary. It also reran selected fixtures with smaller buffers (capacity m instead of m^3). Main-run totals: 98,021 generated full candidates, 93,585 satisfying tuples, 140,353 emitted partial records, 5,727 processed chunks (115 short), zero model-set discrepancies. The sum of minimum plan products W across all fixtures was 99,344; each fixture's actual candidate count was <= its own W. For the XOR and relabelled controls, W=m^3 and the full solution count was one. These are reference semantics and buffer tests, not timings or full original stage executions. The JS table lookup was indexed, not a claimed physical implementation of the sequential joins.
