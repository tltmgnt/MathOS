## 1. Result and why this changes the research route

The recent unconditional quadratic results relied on equal COMPLETE crossing records of all long eligible programs at a common interior cut. The previous estimate grows too fast at stage three. Here is a stronger, constructive limitation: a single fixed original three-symbol one-tape program makes its running-state crossing sequences injective on all binary inputs of the same length, simultaneously at every interior cut. The program always halts with a malformed output. It runs in O(L^2) original transitions, so it is scheduled at its FULL runtime by the exact cubic stage eventually (and by every fixed higher stage). Its concrete description is generated by the submitted compiler: 1046 running states, 48120 description bits. The program is not chosen separately for each input or cut.

Consequently, for all sufficiently large n, the combined complete crossing records of ALL eligible descriptions at stage three have no collisions between different original selector strings at any cut c in [1,L(n)] with head initially left. This remains true when using the earlier compressed exact records because those reconstruct the full crossing states. It applies to the earlier family of separated inputs, including the common-pin choice and the prefix-blind filter with R=Theta(L). The copying program's allocated clock grows cubically and hence exceeds R eventually. It does not assert that all possible crossing-sequence arguments fail, that SAT is easy at stage three, or that unbounded B_3 is empty. The program never solves SAT and can be omitted with a correctness certificate; this is specifically a barrier to retaining every eligible program's full transcript, not to carefully justified reduced records or other methods. A collision count with no collisions cannot be repaired by tighter counting constants alone.

## 2. Concrete three-symbol copying program

The raw input S is L contiguous binary symbols at cells 0..L-1, blanks (symbol 2) elsewhere, head at zero. This includes the original complete selector tape. The machine first converts the raw string to aligned blocks of three binary symbols. Logical symbols 0,1,2,3,4 have codes 000,001,010,011,100; logical blank 5 has code 222. Logical coordinates i occupy physical cells 1+3i through 3+3i. No extra physical symbol, random access, length counter or input advice is used.

Raw conversion: scan right to the initial blank delimiter, then read the last remaining raw bit just left of that delimiter. Erase this bit, remembering its value in the finite control. Seek right across the coded suffix to its first blank. Shift that suffix right by two physical cells, from right to left, remembering each moved binary symbol in the finite control. Stop at the old delimiter (it is still blank). Write the three-symbol code for the saved bit starting at that delimiter. Rewind five cells from the end of the new code (the head is just beyond it) to read the next raw bit. The invariant is raw prefix followed by one blank delimiter followed by a contiguous coded suffix; the raw prefix shrinks by one bit, and the coded suffix increases by three cells. The shifting loop visits the old source positions from right to left and stops at the old delimiter, never overwriting an unread source cell. When no raw bit remains, the delimiter is at cell 0, encoded input occupies cells 1..3L, and the head is aligned at cell 1. Conversion takes O(L^2) original steps: for each bit at most O(L) bounded scans and shifts, with constant steps per shifted cell.

On the logical tape (implemented by the same original table), install delimiters at -1 and L. Use 2 and 3 as marked versions of bits 0 and 1. Process the unmarked input bits from left to right. Mark each chosen bit, remember it in the finite state, scan left across the input and delimiter and append that bit to the outward end of the left copy. Return right across the left copy and input and append the bit to the outward end of the right copy. Return to the left delimiter and scan past marked bits to the next unmarked bit. The copies have no gaps and never overwrite a delimiter. When all bits are marked, scan through the right copy and halt on the next logical blank at coordinate 2L+1. For every j in [0,L-1], the exact terminal tape has the code of S_j in logical cell -2-j and in logical cell L+1+j. Thus both copies independently encode all of S, and the entire left copy lies at negative physical positions while the entire right copy is strictly beyond physical position L. The final physical head is at 1+3(2L+1) on a blank, so for every original n>=1 the output is malformed and cannot pass the verifier.

A logical step reads three physical symbols (remembering the short code in finite control), rewinds three cells, writes the new three-symbol code, and adjusts by at most six cells to the next logical block. This is at most fifteen original transitions per logical step. The finite table generator implements exactly this macro; unspecified malformed-code transitions halt and are never encountered on valid binary input. The logical phase takes O(L^2) logical steps: O(L) scans per input bit, plus linear initialization and termination. For instance each of the L iterations has fewer than 16(L+1) logical transitions, and initialization/termination fewer than 10(L+1); conversion takes fewer than 30(L+1)^2 raw steps. Together these bounds imply the conservative original-step envelope 1000(L+1)^2. The generated table is encoded and decoded using the actual original U syntax, not a high-level virtual machine assumed to have free steps. Fixed code length ell=48120 is very large, so the eventual cubic inclusion threshold need not be remotely practical. Since 2^(3 ceil(log2 L)-ell) >= L^3/2^ell eventually dominates the stated quadratic envelope, every execution on length L halts within the original clock. The exact stage-two clock need not admit its complete run: that is consistent with the preceding unconditional quadratic collision results.

## 3. Full crossing transcript injectivity

Fix L, and cut c in [1,L] between physical cells c-1 and c. The head starts on the left. For a binary S of length L, record the running state after each transition crossing that cut. The halt is at a noncrossing transition on the right (the last macro's head remains strictly to the right of all these cuts), so every crossing state is a running state. Suppose distinct S,S' have equal crossing sequences. Construct a mixed input Z by taking S at cells left of c and S' at cells right of or equal to c, including the fixed exterior blanks. Z is still a contiguous binary string of length L; if S,S' are normalized selectors at the same n, so is Z because the unary header agrees.

The local splicing lemma is particularly simple here, with no rejection certificate needed. A local segment starts either at the original head on the left, or at the boundary cell on the side entered with the crossing state specified by the transcript. Its next transition reads only that side's tape, and the tape edit of an exiting transition is on its departing side. Determinism therefore reproduces that segment on the mixed input from the corresponding original run. Induct over the alternating crossing events; matching transcript states ensure the reproduced departure starts the next local segment with exactly the required state. After the last crossing the final side is the right in both runs, and its reproduced segment halts. The entire final left half-tape is the final left half of the run on S; the entire final right half-tape is the final right half of the run on S'. This argument does not infer anything about unobserved timeouts. Each actual complete execution, including the one on Z, is within the cubic allocation by the uniform runtime bound. If local step counts are included, they are unnecessary for this stronger injectivity statement.

But the two exterior copies in a run on Z must both encode Z. The left copy inherited from S encodes S and the right copy inherited from S' encodes S'. Their locations are fixed by the common input length. Thus S=Z=S', contradiction. This establishes injectivity of even the crossing-state sequence alone, at every such cut. Any exact record from which that sequence is reconstructed is also injective. It is not necessary to record the copy contents, and it is not necessary that the final tape contents be visible to the original verifier.

For the prior method, all long general descriptions are included in one combined record. The copying machine is one of them for every sufficiently large cubic size; even if the prior method restricts the compared inputs to UNSAT or disjoint pairs, they are distinct binary strings, so there is still no collision at any selected cut. No average-record sharpening can show equal complete records of all those programs on distinct inputs. In contrast, an argument that proves some programs cannot accept any constructed input and removes them, or only records a suitable semantic quotient, is not refuted. This specific machine has such an easy certificate. Whether sufficiently many other programs can be soundly removed or compressed remains a separate open problem. No general limitation on all lower-bound techniques is claimed.
