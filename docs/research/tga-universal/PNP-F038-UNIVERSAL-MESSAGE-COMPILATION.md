## A single fixed boundary per input size encodes all 3-CNF satisfiability

Let n>=1 and enumerate every normalized nonempty clause of width at most three over n witness variables x, using distinct variables within each clause and no tautologies. There are m=sum_{j=1}^min(3,n) 2^j binom(n,j)=O(n^3) clauses D_i, including every unit and binary clause. Each p_i is a fresh presence bit. The fixed inside formula I_n expresses all guarded clauses (not p_i OR D_i). A length-three D_i=(l1 OR l2 OR l3) uses a fresh private u_i and the two clauses (not p_i OR l1 OR u_i), (not u_i OR l2 OR l3). A shorter clause is guarded directly. Let s be the number of length-three clauses. For every fixed p and x, the private u_i exist iff x satisfies the selected source clauses; the split gadget is verified by considering u_i=0 or 1. Add the outside formula O_n consisting of (p_i OR v_i) for fresh private v_i. Its projection onto p is the full cube, because all v_i can be one. The total source formula has n+2m+s variables and 2m+s clauses.

All clauses on each exact variable scope occur singly (fresh p_i, u_i or v_i distinguish them). There are no unit clauses in the constructed source and no complete parity class on any scope. Consequently the specified width-three affine extraction leaves the entire formula residual. In the ordinary coordinate direction spaces, the inside/outside intersection is exactly the span of the m presence coordinates, since all other variables are private to one side. Put I_n and O_n in the two children of a supplied binary tree, using arbitrary binary trees within each. The exact inside feasibility message on p is

  R_n(p)=1 iff exists x satisfying every D_i with p_i=1.

The formula, tree, and cut are fixed by n, independent of the query p. All encodings have polynomial length in n. An arbitrary 3-CNF of bit length N can be normalized, renumbered and encoded into p for n=N in polynomial time (handle empty clauses immediately). This gives a single reusable boundary relation per input size that captures SAT, even though the entire constructed formula is itself trivially satisfiable by setting p=0 and v=1. No hard instance must be recognized by a structural heuristic in the proof.

## Representation-independent equivalences

Consider exact boundary compilation for normalized width-three CNFs after the specified extraction, for a supplied tree and node. The output is a description d of the exact message, queried via a single fixed deterministic evaluator E(d,z) running in time polynomial in description and query length. The evaluator must be correct on every boundary signature z; no extra oracle is permitted. The encoding class may be arbitrary, but its evaluator must be uniform and polynomial-time. The theorem concerns existence of some such representation class, not every fixed class.

**Uniform theorem.** There is a polynomial-time exact compiler with polynomial-time evaluation for all such inputs iff P=NP. Forward: build the fixed family, compile the inside message, and evaluate at the presence vector. Reverse: under P=NP, a deterministic polynomial-time algorithm decides membership in any exact message: nondeterministically guess an ambient parameter assignment, check the subtree clauses under the affine parametrization and the supplied boundary signature; extraction, span construction and query checking are polynomial. Use the source, tree, node and basis as the polynomial-size description and this fixed decision algorithm as evaluator. If an actual Boolean circuit output is required, specialize the polynomial-time decision computation to the fixed source, tree and node and unroll it in polynomial time. Inconsistent affine extraction can be handled directly by the empty relation. No claim that a compiler into any particular previously implemented representation becomes efficient.

**Nonuniform theorem.** Every exact message admits polynomial-size Boolean circuits (one common polynomial in explicit source/tree input length), without any efficient construction requirement, iff NP is contained in P/poly. More generally the forward implication holds for any polynomial-size exact descriptions with one uniform polynomial-time evaluator. Forward: choose a polynomial-size description for the fixed family at n=N as advice, compute the presence vector and evaluate. This is a polynomial-time advice algorithm for 3-SAT, hence NP is contained in P/poly by polynomial-time reductions. Reverse: the universal exact-message membership language is in NP as above. Under NP contained in P/poly it has polynomial-size circuits for each input length. Encode source/tree/node/basis and query with fixed-length query fields and polynomial padding. Fix all source-related circuit inputs to the given instance and leave only the boundary signature inputs free. The resulting circuit has polynomial size in that instance's explicit length and computes its message. This is a nonuniform existence argument, not a constructive compiler or a polynomial-size certificate of circuit correctness.

A uniform compiler with superpolynomial preprocessing but polynomial-size output would not by itself imply P=NP. A language with arbitrary large descriptions or a costly evaluator is not covered. The boundary relation need not be compressed by a single uniform polynomial even under assumptions about a fixed easy family. General circuit lower bounds for this fixed universal family would entail the corresponding nonuniform complexity separation; no such lower bound is asserted here.

## Consequence for mixed-message strategy coverage

Universal polynomial construction, including output, conversion, and verification costs, of exact reusable boundary evaluators is a resolution-level obligation independent of the choice of representation. Even granting unlimited preprocessing while demanding universally polynomial-size efficiently evaluable outputs reaches NP versus P/poly. The statements do not lower-bound all SAT algorithms, or claim that computing only the root decision requires materializing every boundary message. Logical preprocessing, different trees, lazy queries and other approaches may avoid this particular message; the fixed-tree obligation is essential. They also do not show that verifying supplied descriptions is easy. Existing exact certificate replay can still be expensive. A claim of efficient general computation must specify whether it constructs reusable exact messages, answers individual queries, or produces only a final witness.
