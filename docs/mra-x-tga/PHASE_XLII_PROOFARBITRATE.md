# Phase XLII — adaptive proof synthesis and format arbitration

The untrusted producer sorts each original factor's rows by (cost, assignment); the first compatible row is an exact conditional minimum. Cache its row and cost (or absence) by unique factor occurrence ID and exact scope-restricted partial assignment, for one search only. Duplicate factors retain distinct IDs. Adaptive branching chooses a variable with the most distinct values among the selected minimizing rows, breaking ties by degree, domain size and name. Cached degree-only search is an ablation: it must produce exactly the old tree and receipt. The mathematical lower-bound rule is unchanged, not a stronger bound. Both Phase XLI partition and Phase XXIII elimination checkers are unmodified. Proofs certify optimum/infeasibility and a feasible witness, not necessarily a canonical tie or integrity of a discarded elimination trace.

select(doc, expected, reads=4) requires the independently trusted original-problem digest. For fewer than two anticipated reads, check the existing elimination certificate. Otherwise attempt the adaptive search within default limits (12000 search nodes, 300000 charged factor queries plus examined rows, 24000 cache entries); accept the independently checked partition proof only if its canonical bytes are smaller. Exhausted or counterexample search, checker ValueError, or non-smaller proof uses the checked elimination fallback; malformed input can be rejected instead. Limits exclude preprocessing/sorting, votes, serialization, checker work and elapsed time; not total CPU/RSS limits. The policy is an implementer-selected size heuristic, not a learned latency predictor. Existing transactional gate, disk formats and defaults unchanged. Optional export research only, no automatic deployment.
