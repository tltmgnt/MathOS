# Phase X — performance-aware compiled reasoning

Run `python tools/mra_x_meta.py --output meta-evidence.json`. No extra packages are needed for the audit. The opt-in solver compiles factor routing and variable-coordinate mappings from scopes and elimination order, caches up to eight structural plans by default, and reuses bucket projections by complete content. Domains remain fixed. For previously unseen scopes it compares the preceding order with a new min-fill order, retaining the preceding order if its full enumeration count fits the budget and is no more than twice min-fill. The factor multiset retains multiplicities. This policy and the threshold were selected by the implementer, not learned from runtime data. There is no local tree repair.

## Informal correctness
A factor is routed to its first variable in the elimination order, or to the terminal accumulator if constant. A projected factor is similarly routed to its first remaining variable. Induction over the compiled steps gives the same buckets, projected minima and tie-broken backpointers as the flat reference. A content hit compares the complete boundary and multiset of coordinate maps and factor tables; fixed domains and variable identity imply identical projection and witness rows. Return a deep-copied trace. The plan cache key uses sorted scopes, including repeated scopes. The enumeration budget is a full-kernel bound, not an end-to-end runtime or memory guarantee. The argument is not mechanized.

## Local audit
12 new-seed synthetic workloads of ten solves each, 8–64 variables, chains/cycles/overlapping ternary factors. All 120 candidate traces matched fresh selected-order results and the Phase VI checker. Five execution paths agreed on all 120 objectives and validated their witnesses (600 results, 96 feasible and 24 infeasible instances); 30 also compared with brute force. Six boundary/budget/eviction/output-mutation controls passed. Two runs reproduced all deterministic evidence and verified both SHA-256 report digests. 48 structural plan hits and 2,312 bucket hits.

Total logical enumerations including setup: meta 13,971, Phase IX adaptive 12,541, fixed min-fill incremental 18,275, fixed hierarchical incremental 13,453, fresh min-fill 35,320. Candidate uses more enumerations than Phase IX and fixed hierarchy, but fewer than fixed or fresh min-fill.

Timing: five repetitions per strategy per workload, randomized deterministic execution sequence, separate traced Python allocation pass. Timings include construction, planning, and results for ten solves; exclude oracle and certificate checking. First run geometric-mean candidate/baseline median-time ratios: 0.345 adaptive, 1.099 fixed min-fill, 0.919 fixed hierarchy, 1.074 fresh min-fill. Second run ratios 0.334, 1.069, 0.859, 1.078 respectively. Worst per-workload slowdown about 45.2% and 39.9% respectively. Median across workload Python traced peaks: candidate 373,740 bytes, adaptive 307,912, fixed min-fill 318,504, fixed hierarchy 439,476, fresh min-fill 197,520. This is not native RSS. There is no external solver performance comparison.

The predeclared promotion gate requires at least 10% geometric-mean runtime reduction against every baseline and no more than 20% per-workload slowdown. Both runs returned NO_PROMOTION. The candidate materially reduced Phase IX overhead but did not beat simpler baselines reliably. No changes to default policies or curriculum acceptance. Next: cached structural updates without full min-fill replanning, bounded dependency-indexed invalidation, a runtime-trained dispatcher with separately held-out workloads, and independent benchmarking. Original RE-X integration, Lean certification, remote CI and independent reproduction remain unverified.
