# Phase XXIII — proof-carrying finite-domain results

Run python3 tools/mra_x_portable.py --directory portable-audit (new directory, system libz3 needed for the additional audit). To check a single JSON certificate, run python3 -I -S tools/mra_x_kernel.py FILE --expect-problem EXPECTED_SHA256. The 113-line standalone checker imports only Python standard-library modules; no MathOS solver or Z3 dependency. The optional expected problem fingerprint must come from an independently trusted description of the intended input. The fingerprint binds the exact serialized problem representation (including factor list and row order), not mathematical equivalence or authenticity. Without it, the checker verifies the problem included in the document.

Schema 1 includes domains, original factors, elimination order, projected tables, minimizing witness rows, terminal optimum, final witness, width and full visit count. Reconstruct buckets from original factors and verified prior messages. For every local assignment, evaluate the factors directly. If feasible, require its (cost, value) pair to be lexicographically no smaller than the claimed pair; require an attaining assignment for each claimed row. No feasible assignment may lack a projection. Then check terminal constants, counts and reverse witness recovery against the original factors. By the Phase XXI local projection argument and induction through the order, an accepted result is exact, assuming the checker implements this specification correctly. This is an informal correctness argument for a portable result certificate, not a machine-checked program proof or exported Z3 proof object.

File loading is bounded to 8,000,000 bytes, duplicate JSON keys and duplicate rows are rejected, and schema fields are checked. Limits: 128 variables, domain sizes 1–4, 1024 original factors, costs and claimed optimum magnitude at most 10^100, 1,000,000 local assignment visits, 5,000,000 factor lookups. These are selected admission and work limits, not absolute CPU/memory or hostile-input security guarantees. Python, the checker, and its standard library remain trusted. -I -S disables ambient imports/site packages; it is not an OS security sandbox. Byte limit applies to the file loader, not direct Python calls. Persistent files are rechecked from scratch, not trusted receipts. No incremental proof checking speedup claim.

## Executed local evidence

Two complete campaigns, each: 22 networks from 11 topology families with four states (initial, domain expansion/reordered migration, forbidden unary insertion, removal), two 128-variable chain states, four boundary cases. 94 certificates, 38 feasible and 56 infeasible; all accepted in fresh isolated Python processes, with identical in-process receipts. 48 small states additionally checked with whole-instance SMT (73 queries). 20,591 local assignment visits, 38,944 factor lookups, 311,534 total certificate bytes, largest certificate 22,120 bytes. 17 negative controls: twelve corrupt document variants, wrong expected fingerprint, oversized enumeration, duplicate JSON key, oversized file, truncated file. The lookup limit is enforced but was not separately stress-tested. Both evidence reports byte-identical; report digest verified. The two large certificates contain 128 variables and require 776 visits each. This is local reproduction, not independent replication. The first audit attempt exposed a relative-path error in the subprocess harness, fixed before both successful runs.

No runtime comparison, authenticated storage, compressed proofs, proof assistant certification, original RE-X physical-logical equivalence or general implementation refinement. No automatic policy promotion or changes to the default solver. CI workflow added; remote CI not confirmed.
