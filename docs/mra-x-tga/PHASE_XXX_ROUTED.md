# Phase XXX — independently routed verification and checked recovery

Run python3 tools/mra_x_routed_audit.py --directory routed-audit (new directory). The opt-in Store subclass maintains the Phase XXVIII database schema and historical read interface. The checker reconstructs routes directly from original factors and verified projected messages using earliest elimination rank; it does not trust the candidate's internal bucket map. Each factor/message is routed once per verification rather than scanning the remaining active list at each rank. All domains, factors, counts, trace rows, local minima, terminal costs and original witness are validated, with exact previous-state receipt equality allowing local enumeration reuse. Canonical comparison binds the prepared factor IDs, domains, budget and certificate to the snapshot. The independently reconstructed engine and new receipts are published after commit; a stale writer or failed transaction cannot advance them in the tested sequential transaction model. On reopening, verify from empty receipts and reconstruct buckets/counts directly from the checked snapshot instead of replaying the solver and then seeding receipts separately. No saved receipt is trusted. Still scans and validates the entire certificate and builds every route each edit; not a fully dependency-local incremental checker. Trust includes Python, the checker, preparation and process memory. No arbitrary malicious code isolation, authentication, power-loss guarantee or formal program proof.

Two local campaigns: nine new-seed streams (8/32/64 initial variables, chains/cycles/overlapping ternary factors), 12 edits each. Per campaign 108 states (99 feasible, nine infeasible) checked by each of three methods (Phase XXVIII, XXIX, XXX).
