# Phase XV — predictive migration arbitration

Run python tools/mra_x_arbitrate.py --output arbitration-evidence.json. The opt-in controller uses Phase XII indexed repair for unchanged domains. For variable/domain edits, compare surviving-order migration, min-fill-order migration, and full min-fill rebuild. New variables are appended to the surviving order. Estimate the full enumeration count and a conservative upper bound on cache misses by propagating known matching messages and unknown markers for all predicted misses. Select minimum upper bound among candidates within the full enumeration budget, breaking ties by full cost and preferring rebuild at equal costs. No future edits are required.

Reuse across reordered states requires exact bucket factor multiset and domain compatibility as in Phase XIV. Induction over the chosen order proves a predicted hit has known equal input and the same projection; unknown messages conservatively count downstream work. Thus actual visits cannot exceed the predicted upper bound. This is an informal argument, not a Lean proof. Ordinary indexed edits record actual work retrospectively rather than predicting it. The bound excludes planning, scans, copies, verification and SQLite I/O. The policy is deterministic, not runtime-trained.

Persist candidate options, selection, actual and full counts atomically with the checkpoint, pruning decision records to the same version window. History verifies individual digests on read; it is not authenticated, and missing history rows are not detected. Restore still replays the mathematical state. Historical telemetry is not yet used to train the selector.
