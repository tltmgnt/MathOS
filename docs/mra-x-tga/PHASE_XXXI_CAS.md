# Phase XXXI — content-addressed transactional memory

Run python3 tools/mra_x_cas_audit.py --directory cas-audit (new directory). The opt-in mra_x_cas.Store uses a new SQLite schema, not an in-place upgrade of Phase XXX databases. It preserves the apply/get/history interface. Three tables store canonical factor and projection/witness objects keyed by SHA-256, per-version manifests and unique object references. The manifest preserves input IDs and multiplicity, domains, order, counts, budget and final result. Before commit use the Phase XXX independent route checker and exact in-process receipt reuse. Prepared inputs, budget and certificate are bound to the candidate snapshot. Store each distinct object once, checking exact bytes against any existing entry. One BEGIN IMMEDIATE transaction checks the current version, inserts new objects/manifest/references, prunes old versions and deletes unreferenced objects. Foreign keys are enabled. Publish reconstructed engine and staged receipts only after commit. Retain 16 versions. On reopen and historical read, check all referenced canonical payload digests and exact reference set, reconstruct the portable certificate/snapshot and verify from empty receipts. No persisted receipt is trusted. Hashes do not authenticate origin; fully replaced valid mathematical histories, rollback attacks and arbitrary hostile Python/DB mutation are not covered. Existing certificate and snapshot byte envelopes are retained. All routes, full snapshot and certificate are still constructed and serialized and every object's bytes are hashed; only persistent object writes are deduplicated. Not a dependency-local verifier, incremental state-hash algorithm, production database migration or hard memory/time bound.

## Local evidence

Two complete local campaigns, six new-seed synthetic streams (8/64 initial variables, chain/cycle/overlapping ternary factors), 12 edits per stream. Each campaign: 72 matched states (66 feasible, six infeasible); both arms match fresh reference and portable certificate fingerprints, exact historical receipts and demand counters. One reopen per arm per stream. 13 controls: three injected candidate errors (objective, count, ID), SQL abort after object insertion with all table contents preserved, zero-new-object no-op, stale writer, invalid domain, duplicate factor multiplicity, retention and garbage collection, expired version, corrupt object, rehashed wrong optimum and missing reference. Additional fresh-process recovery of six final databases verified locally (separate supplemental evidence). Both complete reports reproduced non-timing evidence with verified digests.

Per campaign both stores use 9783 actual solver visits, 25474 full certificate visits, 9720 fresh visits and 1590 reused buckets. CAS edit receipts report 980 new and 4660 existing unique object occurrences (82.62% reuse, excludes initialization), 91488 new object bytes and 473707 manifest bytes inserted. At end of each campaign (six databases, 13 retained versions each): 1196 distinct objects, 5856 unique per-version references, object payload 99048 B plus manifests 494428 B = 593476 B versus 1215988 B of routed snapshot+certificate payload (-51.19%). This logical comparison excludes hash/key columns, reference rows and indexes. Actual SQLite allocated pages including metadata and free pages: CAS 2461696 B vs routed 1421312 B (+73.20%); all six CAS databases are larger. No claim about bytes physically written, journal traffic, vacuuming, or compression.

Three randomized-order repetitions per method per stream (36 timed batches per campaign), includes fresh DB creation, 12 commits, one reopen, four historical verified reads and storage accounting, excludes additional audit reads/reference checks. Geomean of per-stream median CAS/routed time ratios 1.304255/1.296372, worst 1.427923/1.393125. Reopen ratio 1.361549/1.616152; four historical reads ratio 1.398714/1.337623. NO_PROMOTION in both campaigns. Required >=10% geometric mean runtime improvement, worst ratio <=1.2, and no aggregate physical page increase. Long hex references, repeated manifests, multiple indexes and object validation remain costs; not separately profiled. No default change. No independent replication, mechanized kernel proof, original RE-X equivalence, cold-cache, RSS or power-loss test.
