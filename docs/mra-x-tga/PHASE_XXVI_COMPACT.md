# Phase XXVI — compact proof encoding and indexed verification

Run python3 tools/mra_x_compact_audit.py --directory compact-audit (new directory). The compact checker and Phase XXIV archive module use only the Python standard library. Full replay: python3 -S tools/mra_x_compact.py FILE --expect TERMINAL_SHA256. Indexed replay: python3 -S tools/mra_x_compact.py FILE --index INDEX_JSON --target 11 --expect INDEX_SHA256. Use separately trusted canonical digests; the example anchors are generated alongside the artifacts, not authenticated.

Schema 2 replaces repeated hex object references with positional integer references into the current record's object list. An object list entry is either a literal factor/proof object or an integer referring to an object in the previous state's list. Checkpoint records have only literal objects, and the generator uses exact canonical object equality to decide reuse. Factor multiplicity is preserved by the state manifest. All records retain the SHA-256 chain over their entire payload; per-object hashes are no longer transmitted. Mathematical validation uses the same Phase XXIV verify_state routine and exact receipt comparison. New process replay begins without trusted receipts. Index entries contain offset, record byte length, record hash and checkpoint flag. The index is validated against a caller-supplied digest and checked for contiguous bounded offsets. The reader seeks to the nearest preceding checkpoint, checks record sequence, chain, local certificates and final target digest, and checks the ending byte offset. Indexed verification establishes the selected state and the verified segment only, not the preceding or following history. The offset index is for the uncompressed stream; no random-access gzip support. The default interval of eight is a design choice, not an optimized policy.

Limits: 8 MB line, 64 MB read stream or indexed file extent, 128 states, 1152 slots per state and at most 2304 old/new slots, existing local and aggregate verification work bounds. No absolute process-memory or CPU limit, authentication, OS sandbox or mechanized program proof. The exporter builds the full encoded byte string and index in memory; streaming applies to the checker.

## Executed evidence
Six new-seed synthetic streams (chains, cycles, overlapping ternary factors; 8 and 64 variables), 12 states each, including factor value changes, no-ops, infeasibility and recovery, domain expansion and contraction, duplicate factor insertion/removal. Per campaign 72 accepted states (66 feasible, six infeasible), matched full/Phase XXIV/Phase XXV checks with identical incremental counts in the three shared-verifier formats. All 72 targets verified by indexed seek; six separate-process indexed replays. 15 negative controls, including altered index/offset/target hash, wrong record sequence, checkpoint backreference, rehashed wrong optimum, Boolean reference, truncated stream and reduced resource limits. Both runs reproduced every non-timing result, identical streams/indexes/anchors and verified evidence digests.

Full verification visits 25524; incremental fresh visits 8510; 1736/2592 bucket receipts reused. Across every target, independent seek processes 276 state records and 48564 fresh visits versus 468 records and 62908 fresh visits for prefix replay (prefix counts derived from verified full replay). Maximum observed old/new slot count 319. Raw full certificates 599907 B, Phase XXIV archive 216012 B, Phase XXV stream (same interval eight) 721134 B, compact stream 268921 B plus index 6257 B. Interval four compact stream 301816 B. Gzip sizes: full 19304 B, archive 52328 B, legacy 83285 B, compact 28472 B (index excluded). Compact format substantially reduces previous streaming overhead, but does not beat the archive in raw size or full-certificate gzip in compressed size.

Three randomized-order timing repetitions for each of six policies on six streams (108 timed runs per campaign); resident bytes, includes decoding/hashing/verification and gzip decompression when used, excludes disk I/O, generation and seek timings.
