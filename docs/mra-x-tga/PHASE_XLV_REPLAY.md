# Phase XLV — exact-content proof replay and bounded process-local trust

Opt-in mra_x_replay.Cache.verify(kind, raw, expected) accepts only immutable bytes (at most 8 MB), explicit elimination/partition format and a mandatory independently trusted lowercase hexadecimal SHA-256 original-problem digest. On a miss parse duplicate-free JSON, require exact canonical encoding, and run the corresponding unchanged independent checker. Only successful checks insert receipts. Cache key is the entire byte string plus format and expected problem digest; Python dictionary hash collisions require full key equality, not a hash-only match. Values are immutable tuples of scalar receipt fields. Return detached dictionaries. LRU bounded by entry count and sum of retained proof payload bytes (defaults 16 and 524288); proof larger than cache capacity is checked but not retained. clear discards entries; fresh process has no cache trust. Never deserialize receipts or import persisted trust. Hits reuse a previous result rather than independently rechecking mathematical obligations. Trust argument: unchanged canonical bytes, format, checker semantics and expected problem identity imply unchanged checker outcome. Assumes trusted sequential process, unchanged checker implementation/dispatch and no out-of-band mutation of private state. Not a sandbox, concurrent service, proof of implementation correctness, total memory bound, authentication or cross-process receipt authority. Clear/recreate cache on any checker policy/version change. No existing default or persistent storage format changed.

Reproduce python3 tools/mra_x_replay_audit.py --output run1.json and repeat for run2.json. Two completed local campaigns with identical non-timing evidence and verified report digests. 36 fresh seeded problems (27 feasible, nine infeasible; 5–10 binary variables, six families unary/blocks/sparse/chain/cycle/frustrated), two proof formats per problem, original-factor exhaustive oracle and independent checkers agree. Three demand scenarios 1/4/16 reads per proof, 216 scenarios per campaign, three matched methods (already parsed full checker, canonical wire full checker, exact-byte cache). Fresh immutable buffer copies made per request in all methods. Three randomized-order repeats per scenario, 1944 timed batches; separate churn sequence 136 requests, three capacities and five randomized repeats per method, 45 additional timed batches. Excludes solving, generation, encoding, I/O, transaction costs and process startup; cache construction included. Cold cache per repeated scenario. No offline training or model. 20 controls per campaign (including mandatory anchor, malformed input, changed objective and trace, wrong format, detached receipts, entry/byte eviction, bypass, clear, fresh-process cold check); invalid requests do not change cache statistics. 648 matched method-scenario results per campaign plus nine churn results, every request receipt checked against its full-check reference.

Per campaign repeat scenarios: 1512 requests per method; cache 216 full checks and 1296 exact hits (85.71% reused; not fresh independent proofs).
