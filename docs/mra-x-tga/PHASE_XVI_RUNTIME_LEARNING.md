# Phase XVI — persistent migration runtime learning

Run python tools/mra_x_runtime_learning.py --output fresh.json. Training executes admissible migration strategies from identical states (three timing repeats each), stores 135 labeled median-time samples in SQLite, and reloads the fingerprinted model. The policy uses five nearest samples per action, five features (variable and factor counts, predicted and full enumeration, predicted hit fraction) and a 15% predicted improvement threshold over Phase XV. These features and thresholds are hand-selected. Held-out streams have different seeds and sizes; no future edits or held-out updates to the model. Ordinary edits use Phase XII via Phase XV. The model is saved after calibration, not after every training transaction. Training cost excluded from performance gate. The model digest is not authentication.

Two local runs: each has 90 training transactions, 90 held-out transactions and 90 matched Phase XV transactions, plus 405 counterfactual training executions checked against the reference. Nine verified reopens and four controls per run. All committed solutions checked against fresh selected-order reference and certificate checker; shadow runs checked against reference. Held-out learned/Phase XV geometric mean time ratios 0.965225 and 1.050201, worst 1.127190 and 1.271071. Both NO_PROMOTION. Held-out enumerations 26,807 and 26,548 vs 17,100. Five timed repetitions for each of nine workloads per policy per campaign; timing includes durable transaction and initialization, excludes verification, calibration, reopen and model loading. Timing and selected strategy differ between runs. No claim of deterministic model replay, runtime superiority, mechanized proof, independent replication, or original RE-X integration. No default policy changes.
