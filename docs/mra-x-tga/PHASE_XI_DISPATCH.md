# Phase XI — runtime-trained architecture selection

Run `python tools/mra_x_dispatch.py --output dispatch-evidence.json` from repository root. The dispatcher is an opt-in batch selector for five existing engines (fixed incremental min-fill, fixed incremental hierarchy, fresh min-fill, compiled meta, adaptive). Seven normalized features describe size, initial connectivity, arity, mean domain size, batch length, number of distinct scope signatures and scope change frequency. The entire batch's scopes must be known up front; the policy is not an online predictor. It learns relative log runtimes from three nearest training examples and requires a predicted 10% reduction over the best global training engine before departing from that engine. Threshold, features and neighbor count are fixed by the implementer. No training on held-out timings.

## Evidence
Each campaign trains on 18 batches (8/32 variables), tests 18 different-seed batches (16/64 variables), ten solves per batch, across chains, cycles, overlapping ternary factors and three edit regimes. Five timing repetitions per engine per batch, order shuffled deterministically; timings include initialization, feature extraction and dispatch overhead where applicable, but exclude verification. 990 timed batch executions per campaign. 1,980 solution checks per campaign, including full trace replay; 336 feasible and 24 infeasible input occurrences. Ninety small input occurrences also checked by exhaustive enumeration. Four controls passed. Both reports and frozen model fingerprints verified. Earlier fixed incremental engines count actual cache misses, unlike the certificate checker, which counts full logical enumeration; the audit checks the actual count lies within the full count, then normalizes only the counter for certificate replay. This does not independently certify the measured cache-miss count.

The global training winner was compiled meta in both runs. The first dispatch selected meta 17 times and fixed min-fill once; the second selected meta 12 times, fixed min-fill five times and fresh min-fill once. Held-out geometric-mean runtime ratios (dispatcher/baseline): against compiled meta 1.0133 and 0.9838; fixed incremental min-fill 0.8281 and 0.8282; fixed hierarchy 0.6279 and 0.6193; fresh min-fill 0.6698 and 0.6715; adaptive 0.1910 and 0.1943. Both runs failed the predeclared gate of at least 10% geometric-mean speedup and no more than 20% worst-case slowdown against the frozen global training winner. Decision NO_PROMOTION. Timing noise changes the fitted policy and outcomes; these are two repeated local experiments, not independent replication. No new memory or external solver benchmarks. The batch feature vector does not distinguish repeated identical values from fixed-scope value edits, and no real-world workloads were evaluated.

The original curriculum and default execution policy remain unchanged. Next: improve workload features, dependency-indexed invalidation, benchmark independently, and finish original RE-X integration and Lean certification. No claim of 10/10 maturity.
