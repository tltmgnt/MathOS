# Phase XXVIII — unified verified computation and retrieval

Run python3 tools/mra_x_service_audit.py --directory service-audit (new directory). Python 3.11+ required. This is an opt-in local integration prototype, not a network service or a production release.

## Transaction boundary

Use mra_x_service.Store(path, domains) for creation, Store(path) for reopen, apply(edits, domain_edits) for edits, get(version) for verified historical access and history() for retained versions, certificates and demand counts. Reuse Phase XII indexed repair and Phase XV deterministic migration via Phase XVII prepare/execute; no experimental temporal or runtime learner is promoted. Stage the candidate, acquire SQLite BEGIN IMMEDIATE, compare-and-swap the version, run Phase XXIII standalone certificate checking with the prepared problem fingerprint (factors ordered by ID), then persist the checkpoint and certificate together. Failed checks do not advance the committed or live version. Reopen verifies the latest certificate and recomputes the snapshot using Phase XIII restore. Historical reads verify the certificate and compare its problem, messages, trace and order with the stored snapshot. Each successful get increments a capped persisted counter. Retain at most 16 versions; individual snapshot and certificate byte limits are 8 MB. Database pages are not guaranteed to shrink after deletion. No hostile-database, arbitrary Python mutation, concurrent thread, power-loss, authenticated provenance or rollback protection claim. The certificate gate checks mathematical results, not every internal execution invariant.

## Unified representation selection

mra_x_storage.package(versions, docs, kind) constructs one of eight representations: gzip full certificates, content-addressed archive, raw indexed interval 8, or compressed blocks at intervals 1/2/4/8/16. select(versions,docs,demand,queries) tries admissible encodings, minimizes stored bytes plus projected request expenditure (payload bytes, manifest bytes, and four byte-equivalents per conservative full assignment visit), and returns the chosen payload/manifest and candidate scores. Demand weights are successful retained-version DB reads plus one pseudocount. Expected query count is supplied; no predictive time-series model or continuous feedback from exported package reads. The coefficient and candidate set are implementer choices. This is a byte/work surrogate, not an estimate of actual CPU or I/O latency. Encoding all candidates can be expensive; selection and generation are not timed. The in-memory exporter is separate from the DB transaction; package publication is not atomic.

One standalone dispatcher uses the five standard-library checker modules. Run python3 -S tools/mra_x_storage.py FILE MANIFEST --expect MANIFEST_SHA256 --version VERSION. The caller needs a separately trusted canonical manifest fingerprint; sample fingerprints are generated alongside data. Gzip verifies the target only, archive checks all states, raw and block modes verify the selected checkpoint segment. Unvisited history is not certified by target-only retrieval. The compressed and raw formats preserve earlier admission limits; gzip decompression is capped at 16 MB. Physical bytes read, decompression work, index parsing, process memory, hostile-input security and full program correctness are not established by the surrogate. The dispatcher verifies the selected bytes and ignores unreferenced suffix bytes.

## Local evidence

Six new-seed streams (chains/cycles/overlapping ternary factors; 8/32 initial variables), 10 edits per stream and six initial versions. Per campaign: 60 committed edits (54 feasible, six infeasible), every optimum and actual enumeration count matched Phase XV; each optimum also matched fresh reference, and small cases were brute-checked. Solver visits 6932; additional complete precommit certificate visits 11908 (excluding initial states, reopens, historical checks, controls). 18 successful reopens; 144 successful historical request observations, persisted across reopen. 330 all-target retrieval comparisons across selected and four baselines; 72 separately sampled later requests per representation. Observed and later requests use distinct seeds but the same synthetic distributions. Selected gzip on four streams, block2 on two. 11 negative controls including injected bad optimum, stale writer, invalid edit, over-budget edit, expired and missing version, bad anchor, truncated data, rehashed invalid version manifest, corrupted DB certificate hash. Retention tested after 17 extra no-op updates. Two campaigns reproduced all non-timing evidence and verified report digests. Additional supplemental audit on campaign 1: 528 format/target checks covering all eight representations, and eight separate-process retrievals with only the five checker modules present.

Per campaign, aggregate stored bytes including manifests (selected/gzip/archive/raw8/block8): 41520/20740/158770/167506/34051. Sampled request payload bytes: 131000/182568/1893432/681099/163658. Fresh verification visits: 14423/13235/76308/29347/29347. Realized proxy (stored + payload + manifest reads + 4*fresh visits): 307828/322560/2369242/1039997/389461. Selected is 4.57% lower proxy than gzip, but uses roughly twice the storage and more verification visits. 90 timed batches per campaign (1080 individual retrievals), randomized method order, three repetitions per stream. Warm local filesystem opening, manifest loading, decompression and verification included; DB transactions, demand collection, selection, export and cold-cache behavior excluded. Near tie with gzip, not a demonstrated general speedup. NO_PROMOTION; integration and standalone portability validated locally, not a full release.
