# Phase XIII — durable online mathematical state

Run `python tools/mra_x_state.py --output state-evidence.json` with Python 3.11+. The Store API accepts stable factor IDs mapped to replacement factors or None (delete), and optional variable IDs mapped to new domain sizes or None. Unchanged domains use Phase XII indexed repair. Variable/domain changes validate all remaining factors and rebuild a min-fill order; invalid rows or dangling scopes are rejected rather than silently discarded. No future edit stream is required.

SQLite stores each committed version with schema, domain sizes, order, budget, factor IDs and tables, projected messages, witness records and counts. Consumer indices are derived during restore. Each update operates on a staged copy, then uses BEGIN IMMEDIATE and a latest-version comparison to prevent a stale cooperative writer from overwriting a newer commit. The in-memory state changes only after the database commit. On reopening, verify the payload digest, reconstruct the indexed state by full replay, compare all stored projections and traces, and check the solution independently with the Phase VI checker. Restore is deliberately not a fast checkpoint load. Digests are not authentication and consistent malicious replacement of data and evidence is not prevented. Database storage is trusted; no power-loss or process-kill fault injection, retention/pruning, memory bounds for history, or security hardening.

## Local evidence
12 streams of ten commits, 8–64 initial variables (65 after addition), across chains, cycles and overlapping ternary factors. All 120 results matched fresh selected-order execution and independent trace replay; 30 also checked against exhaustive enumeration. 108 feasible, 12 infeasible. 84 unchanged-domain transactions, 36 domain/variable rebuilds, 36 checkpoint reopen comparisons. Seven adverse controls passed (invalid domain shrink, dangling reference, missing factor deletion, budget rejection, stale writer, tampered numerical message with recomputed digest, invalid digest). Full reports byte-identical across two runs. Actual assignment evaluations 23,989 vs 33,897 full fixed-selected-order evaluations, excluding checkpoint replays, staging copies, SQLite I/O and verification. On ordinary edits only: 13,874 vs 23,782. No runtime speedup claim.

Separate local demonstration across three Python process invocations: store a two-variable optimum -2; reopen and apply unchanged edit (zero kernel visits); shrink one domain while replacing the affected table (optimum 3); reopen again and apply unchanged edit (zero kernel visits). This is not a crash-recovery test.

No online learned dispatcher or localized variable-set/order repair, native memory/runtime benchmark, Lean certification, original RE-X integration or automatic deployment. Original curriculum gates remain open.
