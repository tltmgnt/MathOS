# Phase XXVII — adaptive proof storage

Run python3 tools/mra_x_blocks_audit.py --directory blocks-audit (new directory). For indexed verification: python3 -S tools/mra_x_blocks.py FILE INDEX --expect INDEX_SHA256 --target 11. The checker uses only the standard library plus the existing compact and archive checker modules. Obtain the canonical index fingerprint from a separately trusted source; demonstration fingerprints generated alongside the files are not independently authenticated.

Compress each self-contained checkpoint segment with zlib level 6. The anchored index contains contiguous block offsets, compressed and decompressed lengths, block hashes and per-target record hashes. Seek to the block, check its bytes against the anchored hash, decompress with an explicit output bound, verify from the block's checkpoint through the target using the Phase XXVI checker. The remaining block suffix is decompressed and hash-bound but not mathematically verified; other blocks and unvisited history are not checked. Maximum block size is 16 MB compressed and uncompressed, total compressed extent 64 MB, at most 128 states, with existing local/aggregate enumeration limits. These are admission limits, not absolute memory/time guarantees. No OS sandbox or authentication. Export and selection are in-memory; no streaming encoder, live online storage migration or generalized unified storage API.

Selection exhaustively encodes five checkpoint intervals (1,2,4,8,16) and minimizes stored bytes (including index) plus expected number of queries times demand-weighted compressed block bytes. It uses supplied integer demand weights and expected query count, not learned future traffic or runtime prediction. Index read bytes, decompressed bytes, mathematical work and CPU are not part of this score. Encoding overhead is excluded from retrieval timings. The two synthetic profiles correlate with graph size; independent demand and size effects are not established.

Six new-seed streams (12/48 initial variables, chains/cycles/overlapping ternary factors), 12 states each. Per campaign 72 unique states (66 feasible/6 infeasible), 288 all-target checks across four methods; 72 sampled requests per method and six additional isolated-process indexed replays. 14 rejection controls. Selected intervals 8 for each 12-variable stream (uniform demand, three projected queries), 2 for each 48-variable stream (late-state-heavy demand, 30 projected queries). Request sequences drawn separately from supplied distributions after selection. Across sampled requests adaptive processes 180 states/28029 fresh visits, fixed compressed and raw interval 8 each 238/38557; gzip full target-only verification 72/21685. Gzip full parses preceding certificates but checks only the requested certificate using an independently supplied manifest of expected certificate hashes. This is a stronger target-only baseline, not a history verification comparison. Compressed block payload bytes read 173534 vs fixed8 192934; index reads and OS read-ahead are not counted. Gzip/raw physical bytes read are not measured.

Total storage including indexes: adaptive 72811 B, fixed8 compressed 38559 B, raw8 233512 B, gzip full 20774 B. Adaptive costs 88.83% more storage than fixed8 while saving 10.06% compressed payload bytes across the 72 requests; on the sampled finite horizon the sum of storage and payload reads is actually higher (246345 vs 231493). No storage superiority over gzip full. Three randomized-order repeats per method per stream, 72 timed request batches (864 individual retrievals) per campaign. Warm local filesystem open, index read/decode, decompression and checking included; generation, process startup, cold-cache behavior and RSS not measured. Geomean of per-stream median adaptive/fixed8 time ratios .739820/.744609; adaptive/raw8 .764589/.800401; adaptive/gzip full 1.033334/1.115619. Worst relative to gzip full 2.102393/2.214703. Two local campaigns reproduced deterministic report content; report digests checked. NO_PROMOTION: meaningful random-access compressed functionality and favorable measured tradeoff relative to fixed compact replay, but no general superiority over compressed full target-only verification. No independent replication, formal kernel proof, original RE-X integration or confirmed remote CI. No default policy change.
