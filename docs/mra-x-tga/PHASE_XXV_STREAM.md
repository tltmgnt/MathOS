# Phase XXV — streaming proof replay

Run python3 tools/mra_x_stream_audit.py --directory stream-audit (new directory). To verify an NDJSON stream use python3 -S tools/mra_x_stream.py FILE --expect TERMINAL_SHA256. The two checker modules (stream and archive) use only the Python standard library; keep them together. A trusted expected terminal hash is mandatory. It must be obtained separately from untrusted storage; the supplied demonstration anchors are generated alongside the examples, not independently authenticated.

Every record binds its index, previous record digest, checkpoint flag, new objects and full state manifest. The verifier reads one bounded line at a time, retains only the current referenced objects and previous accepted state's exact verification receipts, and releases unused objects. New objects are checked by canonical digest; actual proof reuse is based on exact equality, not a digest. Shared verify_state is extracted from Phase XXIV without changing its mathematical checks. No partial results returned before the final anchor matches. An extracted self-contained checkpoint record can be checked with --checkpoint and its own separately trusted record digest, with no earlier state or receipts. This verifies the selected state, not its preceding history. No byte-offset index or automatic seek API implemented.

Limits: 8 MB per record, 64 MB input (decompressed if a gzip reader is supplied), up to 128 states, 1152 live referenced objects, at most 2304 objects in the merged old/new map, Phase XXIV per-state and aggregate visit limits. Result summaries accumulate up to 128 states. This bounds selected counts, not process RSS or hostile-input memory/time. No OS sandbox, authenticated storage or mechanized program proof.

## Local evidence

Initial larger run (12 streams, 24 states) timed out; completed campaigns use six Phase XXIV streams of 8/32 variables, each repeated twice (16 states), not fresh independent cases. 96 accepted states per campaign (84 feasible, 12 infeasible), agreement with both full certificate and archive checkers, six separate process replays, 24 independently checked checkpoint records, 12 negative controls. 1920 bucket obligations, 1472 receipt hits, full visits 17516 versus fresh 3671 (-79.04%). All non-timing evidence, archive bytes and anchors match across two campaigns; evidence digests verified.

Raw bytes: streamed full certificates 429250; Phase XXIV archive 124788; hash-referenced stream 554072. Gzip bytes respectively 11224, 24803, 50127. Long hex references and periodic self-contained checkpoints inflate the stream. Peak merged object count observed 91; sum of per-stream peaks 326 versus 347 archive objects. No general memory advantage demonstrated.

Two randomized-order timing repetitions per each of five policies per six streams (60 timed executions per campaign), resident bytes including decode/hash/check, gzip decoding when used, excluding I/O and generation. Separate tracemalloc peak per policy. Geometric mean stream/full runtime ratios .9641/.9880; worst 1.3359/1.3177. Stream/Phase XXIV archive 1.2607/1.3010; traced allocation ratio 1.0563/1.0526. Stream/full allocation ratio 1.4403/1.4320. Gzip-stream/gzip-full time .9310/.8994, traced allocation 1.3543/1.3504. No promotion: functional streaming and independently anchored checkpoint access, but worse storage and memory than stronger baselines and slower than Phase XXIV. No independent replication, Lean certification, original RE-X integration or remote CI confirmation. Next improve wire references and checkpoint economics before scaling.
