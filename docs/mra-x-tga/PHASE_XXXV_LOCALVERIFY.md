# Phase XXXV — dependency-local route verification

Run python3 tools/mra_x_localverify_audit.py --directory local-audit (new directory). Opt-in Store subclasses Phase XXXIV and uses prior committed, independently verified routes and receipts as trusted process memory. For unchanged domains and order, validate every serialized factor and proof row, independently compare old and new input factors by ID, update the old routes copy-on-write, and process projected messages in increasing elimination rank. Unchanged routes, projection and witness rows permit reuse of the exact prior receipt without constructing a new key; changed buckets/claims reconstruct the full key and enumerate only if no exact match exists. Terminal cost and original witness checks remain mandatory. Deletions, duplicate factors, constants and witness-only changes preserve their distinct semantics. Domain/order changes fall back to Phase XXXIV full route reconstruction, and reopening and historical access use full verification without trusting disk receipts. Commit candidate routes and receipts only after SQL commit; solver dirty flags and candidate bucket maps are not consulted by the gate. This assumes previously verified process state has not been mutated out of band. It is dependency-local route maintenance, not a completely local checker: full certificate scanning, row decoding, encoding, hashing and witness recovery remain. No authentication, hostile-code isolation, mechanized implementation proof or hardware equivalence.

Adaptive subclass selects zlib memLevel 3 for manifests up to 16384 bytes and 5 otherwise, compression level 1. This is an implementer-selected size heuristic, not a learned controller. The main corpus never selected 5. Separate one-case 128-variable overlapping-ternary diagnostic (sep.instance(35999,128,'triangles'), insert all factors) exercised both modes: 11639 vs 10870 compressed bytes, identical certificate SHA256 and optimum -131, both reopened and verified. Not a measured timing or memory advantage.

Two complete local campaigns, six new-seed synthetic streams (12/48 initial variables, chains/cycles/overlapping ternary factors), 18 edits each. 108 transaction states (100 feasible, eight infeasible), five matched methods, 540 checked method-results per campaign, fresh reference and standalone certificate fingerprint checks, independently restored route/count equality, historical reads, reopen and retained history checked. Each incremental method 9403 fresh visits of 28472 full, 2229 receipt hits; solver 9721 visits. Local path used on 78 edits, 30 fallbacks. Baseline routed/singlepass constructed 3252 keys and inserted 7050 routes, local/adaptive constructed 1722 keys (-47.05%) and performed 3848 route mutations (inserts/deletes; includes fallback inserts, not an equivalent operation-cost metric). 16 controls per campaign: witness-only update, eight injected corruptions, SQL abort and unchanged state, zero-key no-op, stale writer, scope relocation, constant edit, domain fallback and empty-receipt recovery. Both reports' digests verified, exact non-timing evidence matched. Page allocations full/routed 1478656 bytes, singlepass/local/adaptive 344064 bytes (-76.73% vs routed, no gain vs singlepass).

Three randomized repetitions of five methods per six streams, 90 timed batches each campaign. Timing includes creation, 18 transactions, reopen, four historical reads and page accounting; excludes extra reference/standalone checks.
