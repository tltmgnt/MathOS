# Phase XIV — domain-aware state migration

Run `python tools/mra_x_migrate.py --output migration-evidence.json` from the repository root. The new Store extends Phase XIII. Ordinary factor edits use Phase XII indexed repair; variable/domain changes preserve surviving variables' relative order and append new variables in sorted order. This is an opt-in research candidate, not the default.

Migration reconstructs routing in the new order, scanning all buckets. For an existing variable it reuses its projection and witness rows only if the complete factor multiset (scopes, tables, multiplicities) and domain sizes of all variables in the bucket, including the eliminated variable, are identical. Otherwise it recomputes the local minimum. Because messages route forward, induction over the new order gives the same bucket contents and backpointers as fresh execution. The resulting index supports future localized factor edits. This is an informal argument, not a kernel proof. The enumeration budget bounds full selected-order work, not runtime or storage.

Checkpoint insertion and deletion of old rows occur in the same SQLite transaction with a stale-version check. Retention defaults to four versions, configurable 1–64 per open Store. Existing rows are pruned on the next successful write, not at open. This bounds retained row count, not database file size; there is no VACUUM, backup policy or history authentication. Restore still verifies by full replay.

## Executed local evidence
12 streams of ten transactions each across chains, cycles and overlapping ternary factors (8–64 starting variables; 65 maximum). All 120 outputs matched fresh selected-order traces, the Phase VI checker and Phase XIII objective values; 30 also matched exhaustive enumeration. 108 feasible and 12 infeasible. 72 domain/variable migrations, 696 bucket reuses during migrations, 24 verified reopens. Retention row-count checks ran after all 120 transactions. Six controls passed: before-commit and after-commit abrupt subprocess exits, three invalid migrations, and stale-writer rejection. The subprocess exits are not power-loss, filesystem-failure, or pruning-specific crash tests. Two reports were byte-identical; the evidence digest verified.

Candidate evaluations 35,258 versus full same-order recomputation 45,494; Phase XIII actual evaluations 27,783. Domain/variable transactions alone: 24,788 versus full same-order 31,534 and Phase XIII 20,103. Ordinary edits: 10,470 versus full 13,960 and Phase XIII 7,680. The preserved order saved work relative to its own full recomputation, but used more evaluations overall than the Phase XIII policy that replans with min-fill. NO_PROMOTION recommendation; no automatic policy change. Counts exclude global scans, restore replay, database I/O, verification and copies; runtime and memory not measured. Next compare alternative migration orders and full rebuild against a workload-based total-cost objective.

Persistent meta-learning, online learned dispatch, fast verified restore, truly local structural-plan repair, mechanized correctness, original RE-X integration, independent benchmarks and remote CI confirmation remain open.
